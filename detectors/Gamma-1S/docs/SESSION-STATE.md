## Лид из соседнего контура (не проверен)

В корпусе `gamma-spectrum-analysis` появились методические документы ЛСРМ
SpectraLineXX 1.7 с числовыми порогами. Применимо: порог площади пика
≥ 20 000 импульсов на устойчивость формы. Неприменимо без разбора: `χ²/ν ≈ 1`
у ЛСРМ — критерий подгонки ФОРМЫ ЛИНИИ, а в §5.1 отчёта тем же именем названа
мера согласия рядов нуклидов между собой — разные величины. Пороги
пересказаны, не прочитаны; перед использованием читать первоисточник.

## Окружение прогонов и анализа

Чтобы скрипты нашли всё, что им нужно, при пересчёте задаются:

| переменная | значение на этой машине |
|---|---|
| `G4MODELS_BUILD_GAMMA_1S` | `C:/g4work/gamma1s/build` |
| `G4MODELS_PASSPORT_GAMMA_1S` | `C:/g4work/gamma1s/kit_passport.json` (вне репозитория) |
| `G1S_EFR_DIR` | `C:/g4work/gamma1s/ref` |
| `SPECTRAVIBE_ROOT` | корень `gamma-spectrum-analysis` — нужен для чтения двоичных `.spe` ЛСРМ |
| `G1S_LSRM_BACKUP_ZIP`, `G1S_LSRM_CNF` | НЕ заданы; из-за этого `config_drift.csv` — единственная таблица без объявления наблюдаемой |

Прогоны Geant4 запускаются через `. C:/g4work/g4setup.ps1` и `g1s.exe <макрос>
shield` из каталога сборки. ВАЖНО: Geant4 пишет выходной файл В КОНЦЕ прогона —
прерванный прогон не оставляет ничего, частичного результата не бывает.

**Инцидент (задача 144, 31.07 15:03).** Обнаружены ДВА процесса `g1s.exe` на
`th228_long.mac` одновременно (PID 12324 старт 12:18:54, PID 17552 старт
12:51:21) — оба писали бы в один `p5_Th228_long.csv` в конце, гонка на запись.
Причина: скрипт перезапуска после «сбоя» стартовал новый процесс, не проверив
живой ли прежний (прежний не умер, завис только вывод в консоль). Дубликат
(младший, 17552) убит; оригинал (12324) продолжает один. Правило на будущее:
ПЕРЕД перезапуском длинного прогона проверять `Get-Process -Id <PID>`, не
считать «нет вывода в терминале» синонимом «процесс мёртв».
