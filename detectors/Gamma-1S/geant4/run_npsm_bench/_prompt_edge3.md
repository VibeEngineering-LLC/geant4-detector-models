# Спека: анализатор сдвига комптоновского края (этап 4)

Ты — генератор кода на Python 3.11. Верни ОДИН ПОЛНЫЙ файл, без пояснений вне
кода. Комментарии — по-русски. Формат:

```
=== FILE: analyze_edge.py ===
<полный текст>
```

## Назначение

Этап 4: измерить сдвиг комптоновского края, вносимый непропорциональностью.
Это ПЕРВАЯ проверка против чужого измерения (авторы дают −20,0 кэВ для NaI и
¹³⁷Cs), а не против нашего же расчёта.

## Вход

```
python analyze_edge.py --run <csv> [--json out.json]
```

CSV — прогон стенда с моноэнергетическими фотонами. Шапка `ключ,значение`
(нужны `energy_keV`, `npsm_enabled`), затем таблица гистограммы рассеяний,
затем пустая строка и таблица `bin_keV,count_edep,count_light`.

Разбор шапки — импортом `parse_csv` из `analyze_ncompt.py` того же каталога
(`sys.path.insert`). Импорт не удался — громкая ошибка, возврат 3.
Вторую таблицу читать самому: найти строку `bin_keV`, дальше тройки чисел.

## Что считать

**Теоретический край:** `E_edge = E · (2E/511) / (1 + 2E/511)`, где E в кэВ.

**Калибровка.** В шкале СВЕТА пик полного поглощения смещён вниз. Найти его как
бин с максимумом `count_light` в области `[0,2·E, 1,05·E]` (бин 0…1 кэВ
исключить всегда), уточнить положение как центр тяжести по бинам выше половины
максимума. Коэффициент `k = E / положение_ППП_в_свете`.

🔴 **КАЛИБРОВКА УМНОЖАЕТ ШКАЛУ ЭНЕРГИЙ, А НЕ СЧЁТ ОТСЧЁТОВ.**
Правильно: `bin_centers_light = [b * k for b in bin_centers]`, счёт не трогается.
**ЗАПРЕЩЕНО** `calibrated_counts = [c * k for c in count_light]` — от умножения
высоты положение края не меняется вовсе, поиск уходит в область, где края нет, и
упирается в границу диапазона. Эта ошибка уже была допущена ДВАЖДЫ (первая
генерация дала сдвиг −138 кэВ вместо −22,65) — она воспроизводится, если не
запретить её явно.

Все области поиска (плато, окно края) задаются В ЭНЕРГИЯХ и переводятся в
индексы через СВОЮ шкалу для каждой кривой: `bin_centers` для `count_edep`,
`bin_centers_light` для `count_light`. Использовать индекс бина как энергию
запрещено: они совпадают лишь при шаге 1 кэВ и k = 1.

**Положение края — спад до ПОЛОВИНЫ ПЛАТО.** Порядок:
1. Сгладить кривую скользящим средним по 9 бинам.
2. Уровень плато континуума: медиана счёта в области
   `[0,45·E_edge, 0,85·E_edge]`. Точек в ней должно быть не менее пяти, иначе
   возврат «не определено».
3. Порог: половина уровня плато.
4. Идти вправо от `0,85·E_edge` до первого бина, где сглаженный счёт впервые
   опускается НИЖЕ порога, а предыдущий был выше; положение уточнить линейной
   интерполяцией между этими двумя бинами. Дальше `1,35·E_edge` не идти.

⚠ **ЗАПРЕЩЕНО определять край как точку минимума производной** (самый крутой
спад в окне). Так было в первой редакции, и метод оказался неустойчив: он
ловил посторонние структуры — обратное рассеяние, escape-пик иода (28,6 кэВ),
статистические выбросы, — и какая из них окажется круче, зависело от энергии.
Измеренный разброс: сдвиг выходил **+15,8 кэВ при 300 кэВ, −22,7 при 662 и
+527 при 2000** (инцидент W-061). Уровень, задаваемый плато, к одиночному
выбросу нечувствителен.

Обе кривые (по энергии и по калиброванному свету) обрабатываются ОДНИМ И ТЕМ ЖЕ
кодом: систематика метода сокращается в их разности.

**Считать для ДВУХ кривых одного и того же прогона:**
- `count_edep` — шкала энергии, край здесь эталонный, модель на него не влияет;
- `count_light` после калибровки на `k` — здесь край смещён моделью.

**Сдвиг** = положение края по свету (калиброванному) − положение края по энергии.

## Критерии (назначены ДО прогона, из плана)

| № | Критерий | Порог |
|---|---|---|
| К-1 | край по ЭНЕРГИИ совпадает с теоретическим | расхождение ≤ 8 % от `E_edge` |
| К-2 | знак сдвига отрицательный | сдвиг < 0 **на ВСЕХ поданных энергиях** |
| К-3 | величина сдвига при 662 кэВ | 12…28 кэВ по модулю (рамка вокруг опубликованных 20,0) |
| К-4 | прогон с `npsm_enabled = 0` | сдвиг не более 3 кэВ по модулю |
| **К-5** | **воспроизводимость: сдвиг растёт по модулю с энергией** | **монотонно, не менее чем на 3 точках** |

**К-5 введён после W-061.** Совпадение единственного числа с опубликованным
подтверждает вычисление, но не метод: проверка обязана идти не менее чем по
трём энергиям, и критерий формулируется по их совокупности. К-2 по той же
причине переформулирован с одной точки на все поданные.

К-1 смягчён с абсолютных 5 кэВ до 8 % от `E_edge`: при 3 МэВ край шире, и
жёсткий абсолютный допуск был назначен без учёта масштаба.

К-1 проверяет сам метод поиска края: если он не находит известный край в
шкале энергии, его показания в шкале света ничего не значат.
К-4 — мутация; при выключенной модели свет тождествен энергии, и сдвиг обязан
исчезнуть. Если прогон с выключенной моделью не подан — К-4 объявляется
непроверенным, итог FAIL.

## Вывод

1. Одна строка на файл, СТРОГО в формате CSV с этими полями по порядку:
   `E_keV,E_edge_theor,edge_by_energy,peak_light,k,edge_by_light,shift`
   Числа — с тремя знаками после запятой, разделитель запятая, пробелов нет.
   Перед строками — заголовок с теми же именами. Такой формат нужен, чтобы
   результат читался скриптом, а не только глазами.
2. Блок «КРИТЕРИИ» К-1…К-4 с порогом, фактом, PASS/FAIL.
3. Блок «ТРЕБУЕТ ТОЛКОВАНИЯ» (печатать всегда): если в области края меньше
   200 отсчётов суммарно; если производная имеет несколько сравнимых минимумов
   (различие менее 20 %) — значит край размыт и точка перегиба неоднозначна.
4. Итог `STAGE4_EDGE_SHIFT=<число> keV` и `STAGE4_ACCEPTANCE=PASS|FAIL`.

## Ограничения

- `sys.stdout.reconfigure(encoding="utf-8")` первой строкой в `main`.
- Только stdlib + numpy, scipy НЕ использовать.
- Никаких тихих пропусков: нет данных в области — сообщение и ненулевой возврат.
- Несколько файлов можно подать через `--run` несколько раз.

### Донор parse_csv (analyze_ncompt.py)

```python
import csv
import math
import glob
import argparse
import pathlib
import sys
import json

sys.stdout.reconfigure(encoding="utf-8")

def parse_csv(file_path):
    data = {}
    table = []
    try:
        with open(file_path, "r", encoding="utf-8") as f:
            for line in f:
                if line.startswith("#"):
                    continue
                if "," in line:
                    key, value = line.strip().split(",", 1)
                    # Приводим к числу ОДИН РАЗ при чтении — все потребители
                    # ниже получают уже числа. Точечная конвертация по списку
                    # ключей оставляла mean/sem строками и роняла критерии K1/K2.
                    if key in ("em_deex", "crystal_mm"):
                        data[key] = value            # заведомо строковые поля
                    else:
                        try:
                            data[key] = int(value)
                        except ValueError:
                            try:
                                data[key] = float(value)
                            except ValueError:
                                data[key] = value
                elif line.strip() == "n_compt,count_absorbed,count_all":
                    continue
                elif line.strip().startswith("0,"):
                    break
            for line in f:
                if "," in line and not line.startswith("#"):
                    parts = line.strip().split(",")
                    if len(parts) >= 3:
                        table.append([int(parts[0]), int(parts[1]), int(parts[2])])
    except Exception as e:
        print(f"ПРЕДУПРЕЖДЕНИЕ: Не удалось прочитать файл {file_path}: {e}")
        return None
    if "energy_keV" not in data or "mean_ncompt_absorbed" not in data:
        print(f"ПРЕДУПРЕЖДЕНИЕ: В файле {file_path} отсутствуют необходимые поля")
        return None
    data["table"] = table
    return data
```
