🔴 **Все десятичные дроби здесь записаны ТОЧКОЙ** (`0.5`, `1.35`, `3.0`). Если

## Назначение

Измерить сдвиг комптоновского края **методом точки перегиба** — тем же, что
применяют авторы первоисточника (Nat Commun 14:7790, SI раздел S1.4): положение
края определяется как экстремум первой производной спектра, сдвиг — как разность
положений для двух кривых, **приведённых к ОДНОМУ разрешению**.

Прежняя редакция (половина плато) устойчива, но даёт величину вдвое меньше
авторской; прежде-прежняя (минимум производной без сглаживания) была неустойчива.
Здесь производная берётся сглаженной, а кривые уравниваются по разрешению —
это две поправки к тому, что уже пробовалось.

## Вход

```
python analyze_edge_v3.py --mode internal --run <csv> [--sigma-intr <%>] [--json out.json]
python analyze_edge_v3.py --mode measured --calc <csv> --spe <path> [--json out.json]
```

- `internal` — сравниваются ДВА СТОЛБЦА ОДНОГО прогона: `count_light` против
  `count_edep`. Отвечает на вопрос «насколько модель сдвигает край относительно
  истинной энергии».
- `measured` — сравниваются ИЗМЕРЕННЫЙ спектр и расчёт с ВЫКЛЮЧЕННОЙ моделью.
  Это авторская постановка: у них измерение против Монте-Карло с пропорциональным
  откликом. Расчётный файл обязан иметь `npsm_enabled = 0`, иначе громкая ошибка
  и возврат 3.

## Чтение расчётного CSV — устройство файла

Шапка `ключ,значение` (двухколоночные строки). Затем **ДВЕ таблицы**: сначала
гистограмма рассеяний с заголовком `n_compt,count_absorbed,count_all`, потом
спектр с заголовком `bin_keV,count_edep,count_light`. Обе трёхколоночные,
различать по числу колонок НЕЛЬЗЯ — собирать строки только ПОСЛЕ заголовка
`bin_keV`.

🔴 **Таблица спектра РАЗРЕЖЕНА:** записаны только непустые бины, и индекс строки
в массиве НЕ равен энергии. Шкала берётся из поля `bin_keV`. Бины ниже 1 кэВ
отбрасываются всегда — там события без депозита (в пробном прогоне это 96 % всех
строк по счёту).

Из шапки нужны: `energy_keV`, `npsm_enabled`, `n_events_processed`.

## Чтение измеренного спектра — ГОТОВЫМ ПАРСЕРОМ

```python
import sys
sys.path.insert(0, r"<каталог справочных материалов контура> Скилы\0_Work\gamma-spectrum-analysis\scripts")
from gamma.io.lsrm_spe import read_lsrm_spe
```

Нужны `counts`, `live_time`, `energy_cal` (коэффициенты полинома по возрастанию
степени, канал → кэВ), `extras["lsrm_peaks_table"]`.

🔴 Полином переводит КАНАЛ в ЭНЕРГИЮ. Подставлять в него энергию, чтобы получить
канал, НЕЛЬЗЯ. Строить шкалу так: энергия каждого канала `E[ch]`, затем
`numpy.interp` по этой шкале. Счёт канала перед интерполяцией поделить на ширину канала в кэВ. Ширина
канала `i` берётся как `numpy.gradient(E)[i]`, что для внутренних каналов равно
`(E[i+1] - E[i-1]) / 2` — это и есть ширина канала при шаге 1 по номеру; на
краях массива `gradient` переходит на односторонние разности, и это приемлемо,
поскольку края далеко от окна поиска. Без деления плотность исказится: шаг по
энергии переменный (полином 3-й степени).

## Разрешение прибора

Гамма-1С (`--mode measured` и `internal` для его прогонов):

```
FWHM_W(E) = -6.2914323508675 + 1.7442782325498*sqrt(E) + 0.0049483216398*E
sigma_W(E) = FWHM_W(E) / (2*sqrt(2*log(2)))
```

Проверено: при 661.658 кэВ даёт 41.850 против 41.85 в таблице пиков файла.
Область применимости 50…1900 кэВ (реперы прибора 59.5…1836); ниже 13 кэВ
выражение отрицательно и смысла не имеет — при запросе ниже 50 кэВ печатать
предупреждение в блок толкования.

## Приведение к ОДНОМУ разрешению — ядро редакции 3

Обе сравниваемые кривые обязаны иметь одинаковую ширину аппаратной функции,
иначе разность положений края содержит вклад разного размытия, а не только
непропорциональности.

**Режим `internal`:**
- `count_edep` (шкала энергии, размытия нет вовсе) → свернуть с `sigma_W(E)`;
- `count_light` (уже содержит собственный разброс модели `sigma_intr`) →
  свернуть с `sqrt(sigma_W^2 - sigma_intr^2)`.

`sigma_intr` берётся из ключа `--sigma-intr` в ПРОЦЕНТАХ от энергии (умолчание
1.62), то есть `s_i = sigma_intr*E_edge/100` в кэВ.

**Общее правило (работает в обоих случаях):** обе кривые доводятся до одной
целевой ширины `sigma_target = max(sigma_W, s_i)`:

```
добавка к свету  = sqrt(sigma_target^2 - s_i^2)      # свет уже имеет s_i
добавка к энергии = sigma_target                      # энергия не имеет ничего
```

При `s_i < sigma_W` это даёт `sigma_target = sigma_W`, свет сворачивается с
`sqrt(sigma_W^2 - s_i^2)`, энергия с `sigma_W` — обычный случай,
`equalized = ok`.

При `s_i >= sigma_W` получается `sigma_target = s_i`: свет сворачивается с нулём
(остаётся как есть), энергия — с `s_i`. Ширины всё равно равны, но целевое
разрешение задано МОДЕЛЬЮ, а не прибором; пометить `equalized = fallback` и
вывести строку в блок толкования: «целевое разрешение задано sigma_intr, а не
прибором».

🔴 Ошибочный вариант, который НЕЛЬЗЯ реализовывать: свернуть свет с нулём, а
энергию с `sqrt(sigma_W^2 + s_i^2)`. Тогда свет имеет ширину `s_i`, а энергия
`sqrt(sigma_W^2 + s_i^2)` — ширины НЕ равны, и весь смысл уравнивания теряется.

**Режим `measured`:** измеренный спектр уже имеет разрешение прибора;
`count_edep` расчёта сворачивается с `sigma_W(E)`. Столбец `count_light` в этом
режиме не используется вовсе.

**Порядок операций — строго такой:**
1. калибровка света (только `internal`, см. ниже);
2. интерполяция на общую сетку;
3. свёртка НА ОБЩЕЙ СЕТКЕ.

🔴 Свёртка ДО приведения к общей сетке теряет правое крыло: при выключенной
модели свет тождествен энергии, шкала обрывается на энергии источника, и
размытию некуда лечь. Так уже было.

## Калибровка света (режим `internal`)

Пик полного поглощения в `count_light` смещён вниз. Найти его как бин максимума
в области `[0.3*E0 ; 1.05*E0]` по ЭНЕРГИЯМ из `bin_keV` (не по индексам),
исключив бины ниже 1 кэВ. Положение уточнить центром тяжести по бинам выше половины максимума, **беря
только правую значимую связную группу**.

Определения, без которых это неисполнимо:
- бины, попавшие в область поиска, упорядочены по возрастанию `bin_keV`;
- **связная группа** — максимальная подпоследовательность ПОДРЯД ИДУЩИХ (по
  этому порядку) бинов, у каждого из которых счёт выше половины максимума;
  группа обрывается первым же бином со счётом ниже порога;
- **значимая группа** — та, чья сумма счёта составляет ≥ 20 % от суммы счёта
  наибольшей по этой сумме группы;
- берётся значимая группа с наибольшим `bin_keV`, центр тяжести считается
  только по её бинам.

Иначе при 300 кэВ в центр тяжести попадает escape-пик иода (28.6 кэВ ниже пика),
`k` завышается и сдвиг выходит положительным; а при слабой статистике одиночный
далёкий выброс, будучи «самой правой группой», уводит `k` в другую сторону —
отсюда порог значимости.

`k = E0 / положение_пика`, и `centers_light = bin_keV * k`.

🔴 Калибровка умножает ШКАЛУ, а не счёт: `count_light` НЕ трогать. Умножение
счёта на `k` уже допускалось дважды и давало сдвиг −138 кэВ.

## Общая сетка

`E_edge_theor = E0 * (2*E0/511) / (1 + 2*E0/511)`.

```
lo = max(50.0, E_edge_theor - 6*sigma_W)
hi = min(1.35*E_edge_theor, 1.05*E0)
grid = arange(lo, hi + 1.0, 1.0)
```

Шаг 1 кэВ. Интерполяция линейная, вне области — нули
(`numpy.interp(..., left=0.0, right=0.0)`).

🔴 Нижнюю границу нельзя писать константой 50: при малых `E0` край окажется
ниже неё, сетка выйдет пустой либо не покроет окно поиска. Если после расчёта
`hi - lo < 6*sigma_W` — данных на окно не хватает: сообщение в stderr и возврат
3, молча не продолжать. Если `E_edge_theor < 60` — формула разрешения вне своей
области применимости: сообщение и возврат 3.

## Положение края — ТОЧКА ПЕРЕГИБА

1. Окно поиска в энергиях: `[E_edge_theor - 3*sigma_W ; E_edge_theor + 3*sigma_W]`.
   Если окно выходит за границу сетки более чем наполовину — «край у границы
   данных», результат `None`, строка в блок толкования.
2. Производная — **локальной полиномиальной регрессией 2-й степени** в скользящем
   окне полушириной `w = max(3, round(sigma_W))` бинов: в каждой точке подогнать
   параболу по точкам `[i-w ; i+w]` (`numpy.polyfit` степени 2) и взять
   производную подгонки в центре окна. Это сглаженная производная; отдельного
   сглаживания счёта делать НЕ нужно.
3. Положение края = **минимум** этой производной (самый крутой спад) внутри
   окна. Уточнить параболой по трём точкам вокруг минимума:
   `x* = x_min + 0.5*h*(d[i-1] - d[i+1]) / (d[i-1] - 2*d[i] + d[i+1])`, где `h` —
   шаг сетки; если знаменатель нулевой, брать `x_min`.
4. Если минимумов производной несколько и второй по глубине отличается от
   первого менее чем на 20 % — строка в блок толкования «край размыт,
   перегиб неоднозначен».

## Сдвиг

- `internal`: `shift = pos(light_equalized) - pos(edep_equalized)`;
- `measured`: `shift = pos(измеренный) - pos(расчёт off, размытый)`.

В обоих случаях величина обязана быть отрицательной. Знак согласован с авторским
определением `-ΔE := c_sim - c_exp`: их положительное `-ΔE` отвечает нашему
отрицательному `shift`.

## Статистическая погрешность сдвига

Бутстреп: 200 повторов, в каждом счёт каждого бина обеих кривых разыгрывается
как пуассоновский с текущим средним (`numpy.random.default_rng(seed).poisson`),
процедура повторяется целиком, берётся стандартное отклонение полученных
`shift`. Печатать как `shift_err`.

Зерно — ключ `--boot-seed`, умолчание 12345. Оно вынесено в ключ намеренно:
одно фиксированное зерно делает результат воспроизводимым, но не показывает,
устойчива ли сама оценка погрешности; повтор с другим зерном — дешёвая проверка,
и она должна быть возможна без правки кода.

Для измеренного спектра розыгрыш вести по СЫРЫМ отсчётам канала, а не по
плотности после деления на ширину.

## Критерии — назначены ДО прогонов, менять запрещено

| № | критерий | порог |
|---|---|---|
| К-1 | край по энергии (или расчётный в `measured`) совпадает с теоретическим | ≤ 8 % от `E_edge_theor` |
| К-2 | знак сдвига отрицательный | `shift < 0` |
| К-4 | мутация: прогон с `npsm_enabled = 0` в режиме `internal` | `abs(shift) <= 3` кэВ |

Пояснение к К-4, чтобы не выглядело противоречием. Режим `internal` описан как
отвечающий на вопрос «насколько модель сдвигает край», и подавать в него прогон
с ВЫКЛЮЧЕННОЙ моделью кажется бессмысленным — но это и есть мутация: при
`npsm_enabled = 0` световой выход тождествен выделенной энергии, оба столбца
совпадают побитово, и сдвиг ОБЯЗАН выйти нулевым с точностью до сетки. Если он
выходит ненулевым, метод измеряет собственный артефакт, а не физику. Прогон с
выключенной моделью подаётся тем же ключом `--run`; никакого особого режима для
мутации заводить не нужно.
| К-6 | устойчивость к уравниванию: сдвиг, посчитанный БЕЗ приведения к общему разрешению, против посчитанного С приведением | различие печатается; PASS, если `abs(разница) <= 2*shift_err` |

К-3′ и К-5′ проверяются НЕ здесь — они требуют нескольких энергий и сравнения с
измерением; этот скрипт даёт для них числа `shift` и `shift_err`.

К-6 требует считать сдвиг ДВАЖДЫ: с уравниванием и без него. Оба числа в вывод.

## Вывод

1. Одна строка CSV с заголовком, поля строго в этом порядке:
   `mode,E_keV,E_edge_theor,pos_a,pos_b,shift,shift_err,shift_raw,k,equalized`
   где `pos_a` — положение края первой кривой (свет либо измерение), `pos_b` —
   второй (энергия либо расчёт), `shift_raw` — сдвиг без уравнения разрешений,
   `equalized` — `ok` либо `fallback`. Числа с тремя знаками после точки.
2. Блок «КРИТЕРИИ» К-1, К-2, К-4, К-6 с порогом, фактом, PASS/FAIL.
3. Блок «ТРЕБУЕТ ТОЛКОВАНИЯ» — печатать ВСЕГДА, даже пустым: неоднозначность
   перегиба; край у границы данных; `equalized=fallback`; менее 200 отсчётов
   суммарно в окне поиска; запрос ниже 50 кэВ.
4. Итог `EDGE_V3_SHIFT=<число> keV` и `EDGE_V3_ACCEPTANCE=PASS|FAIL`.
