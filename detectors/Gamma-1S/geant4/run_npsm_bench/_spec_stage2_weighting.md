# Спека этапа 2: взвешивание светового выхода в существующем стенде

Расширяется ГОТОВЫЙ проект `run_npsm_bench`, второй стенд не создаётся. Файлы
`NpsmLightYield.hh/.cc` генерируются отдельно по `_spec_npsm_light_yield.md`;
здесь — их подключение и изменения в остальных классах.

> **Статус документа (05.09, ночь): это КОНТРАКТ этапа, а не задание генератору.**
> Настоящий файл описывает ИЗМЕНЕНИЯ существующих классов; локальная модель на
> таком описании работает хуже, чем на задании «верни файл целиком». Поэтому
> задания генератору вынесены в три отдельных файла, каждый со своей базой
> (текущим текстом файлов) и требованием вернуть ПОЛНЫЕ файлы:
>
> | Задание | Файлы | Промпт (задание + база) |
> |---|---|---|
> | `_spec_s22_A_generator_stepping.md` | `NpsmBenchPrimaryGeneratorAction.*`, `NpsmBenchSteppingAction.*` | `_prompt_s22_A.md` |
> | `_spec_s22_B_event_run.md` | `NpsmBenchEventAction.*`, `NpsmBenchRunAction.*` | `_prompt_s22_B.md` |
> | `_spec_s22_C_main.md` | `main.cc` | `_prompt_s22_C.md` |
>
> Задания выполняются ПОСЛЕДОВАТЕЛЬНО: база следующего собирается из уже
> обновлённых файлов, иначе генератор увидит старые интерфейсы. `CMakeLists.txt`
> и объявление `NpsmLightYieldSelfTest()` правятся вручную — по строке каждое.
>
> Требования этого контракта при переносе в задания ДОПОЛНЕНЫ: суммы
> `sum_edep_MeV` / `sum_light_MeV` и счётчик `n_with_edep` (изменение B5).
> Без них критерий П-3 (кривая «свет/энергия») не вычисляется вовсе — в первой
> редакции контракта были только спектры, а среднее по спектру с шагом 1 кэВ
> даёт ошибку округления порядка проверяемого эффекта.

## Зачем

Проверить перенос модели непропорциональности в код переноса против
НЕЗАВИСИМОГО расчёта (кривая `analysis/out/npsm_NaI_light_yield.csv`, этап 0).
Это единственный этап, где реализация сверяется не с чужим измерением, а с
собственным расчётом по тем же формулам, выполненным другим способом.

## Изменение 1: генератор — выбор частицы и режим пучка

`NpsmBenchPrimaryGeneratorAction` получает два новых статических поля:

- `static std::string gParticle;` — `"gamma"` (умолчание) либо `"e-"`;
- `static bool gPencilBeam;` — `false` (умолчание: изотропный поток со сферы,
  как сейчас) либо `true`.

При `gPencilBeam == true` частица стартует из центра кристалла `(0,0,0)` в
направлении `+z`. Обоснование в комментарии: для проверки кривой отклика нужен
электрон, который затормозится ЦЕЛИКОМ внутри кристалла; запуск с поверхности
сферы дал бы электрону пройти вакуум и войти через грань, теряя часть энергии
на краевых эффектах. Пробег электрона 3 МэВ в NaI около 4 мм, кристалл 102 мм —
условие полного торможения выполняется с большим запасом.

Ключи CLI в `main.cc`: `particle=gamma|e-` и `beam=iso|pencil`. Неизвестное
значение — сообщение в stderr и возврат 2.

## Изменение 2: модель в `SteppingAction`

`NpsmBenchSteppingAction` получает указатель на `NpsmLightYield` (передаётся
конструктором, проверяется на nullptr с `abort()` — см. W-053).

В теле, ВНУТРИ уже существующей ветви накопления энергии в кристалле
(`edep > 0 && preVol->GetLogicalVolume() == crystalLV`), добавляется расчёт
веса. Логика строго такая:

```
1. Определить тип частицы шага: track->GetDefinition().
   Если это НЕ e- и НЕ e+ → вес 1.0 (взвешиванию подлежат только они),
   накопить edep и edep*1.0, выйти из ветви.

2. Иначе вычислить S (МэВ/см) по ДВУМ ВЕТВЯМ:

   ветвь «шаг»: если stepLength > kMinStepMm (константа 1e-4 мм):
       S = (edep / MeV) / (stepLength / cm)

   ветвь «локальный депозит»: иначе (шаг практически нулевой — частица
       остановлена, либо энергия оставлена на месте, либо это продукт
       атомной деэкситации):
       S = fEmCalc.ComputeElectronicDEDX(Ek, particle, material, DBL_MAX)
       где Ek = preStepPoint->GetKineticEnergy(), material — материал кристалла.

3. Вес = fLightYield->Weight(S). Накопить в событие ДВЕ величины:
   edep (как сейчас) и edep * вес (новая).
```

### Почему ComputeElectronicDEDX, а не GetDEDX — реализовать именно так

`G4EmCalculator::GetDEDX(...)` возвращает ОГРАНИЧЕННУЮ тормозную способность:
потери выше порога продукции отнесены к дельта-электронам и в неё не входят,
поэтому значение зависит от `emcut`. Модель непропорциональности описывает
плотность возбуждений вдоль трека — величину физическую, от нашего
вычислительного порога не зависящую. Нужна ПОЛНАЯ электронная тормозная
способность: `ComputeElectronicDEDX(Ek, particle, material, DBL_MAX)`.
Это соответствует функции `EDEDXT` в реализации авторов модели.

`G4EmCalculator` — член класса, НЕ создаётся на каждом шаге (дорого).

## Изменение 3: накопление и выход

`NpsmBenchEventAction`: второе поле `fEdepLightMeV` с тем же жизненным циклом,
что `fEdepMeV`; обнуляется там же; передаётся в `RecordEvent` дополнительным
аргументом.

`NpsmBenchRunAction`: два спектра вместо одного.
- `static constexpr int kNBins = 3200; static constexpr double kBinKeV = 1.0;`
- `std::array<long long, kNBins> fSpecEdep{}` — по выделенной энергии;
- `std::array<long long, kNBins> fSpecLight{}` — по взвешенной величине.
Событие попадает в бин `int(value_keV / kBinKeV)` при `0 <= bin < kNBins`;
значения вне диапазона считаются в `fNOverflow` и в спектр не идут.

В шапку CSV добавляются строки:
```
npsm_enabled,<0|1>
npsm_eta,<...>
npsm_s_ons,<...>
npsm_s_trap,<...>
npsm_s_birks,<...>
npsm_bad_s_count,<BadSCount()>
npsm_out_of_range_count,<OutOfRangeCount()>
particle,<gamma|e->
beam,<iso|pencil>
n_overflow,<...>
```
После существующей таблицы гистограммы рассеяний добавляется вторая таблица:
```
bin_keV,count_edep,count_light
```
Пустые бины пропускаются (иначе файл на 3200 строк при десятке заполненных).

## Изменение 4: ключи CLI модели

`npsm=on|off` (умолчание `off`), `npsm_eta=`, `npsm_ons=`, `npsm_trap=`,
`npsm_birks=`. Значения передаются в `SetParameters` ДО `Initialize()`.
При `npsm=off` модель выключена и `Weight` возвращает ровно 1.0 — прогон обязан
дать спектр по свету, побитово совпадающий со спектром по энергии. Это
контрольная проверка, а не украшение.

## Приёмка этапа (что будет проверяться после сборки)

1. `NpsmLightYieldSelfTest()` возвращает 0 — вызывается из `main.cc` при ключе
   `selftest` и завершает программу без `BeamOn`.
2. `npsm=off`: спектры по энергии и по свету совпадают побитово; в CSV
   `npsm_bad_s_count,0`.
3. `particle=e- beam=pencil npsm=on`, серия моноэнергетических электронов
   1…3000 кэВ: отношение «средний свет / энергия», нормированное на 662 кэВ,
   совпадает с `analysis/out/npsm_NaI_light_yield.csv` в пределах 3 % при
   E > 5 кэВ; максимум кривой в интервале 8…12 кэВ.
4. Тот же прогон при `emcut=0.05` и `emcut=1.0` даёт кривые, совпадающие в
   пределах 1 % — доказательство, что взята полная, а не ограниченная тормозная
   способность.
5. Мутация: `npsm_eta=1e-9` — максимум кривой обязан исчезнуть (проверено на
   этапе 0: без члена Онзагера кривая монотонна).
6. Мутация: ветвь локального депозита заменена на `S = edep/stepLength` для всех
   шагов — свет на энергиях ниже 20 кэВ обязан просесть.
