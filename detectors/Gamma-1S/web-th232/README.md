# Разложение спектра тория-232 в маринелли: два метода

Публичная страница для комплекта поверки Гамма-1С (NaI(Tl) Ø63×63,
маринелли 1 л). Аттестационный спектр Th-232 партии 420-7-17 (1940 Бк/кг
± 6 %) разбирается двумя независимыми методами и сравнивается с паспортом.

## Что на странице

**Метод 1: МК-шаблоны по нуклидам** — одновременная подгонка полного
спектра линейной комбинацией восьми модельных шаблонов индивидуальных
звеньев ветви (Th-232, Ac-228, Th-228, Ra-224, Rn-220, Pb-212, Bi-212,
Tl-208; каждый — отдельный Geant4-прогон полного распада только своего
нуклида) и измеренного фона той же геометрии (NNLS, пуассоновские веса
с систематическим полом 3 %). Одна амплитуда на всю ветвь — в вековом
равновесии активности звеньев тождественно равны. Переключатель
показывает альтернативное разложение с гипотезой утечки торона
(Rn-220 — газ): две независимые амплитуды вместо одной, разделённые по
месту Rn-220 в ветви.

**Метод 2: библиотека γ-линий × полная матрица отклика R(E→i)** —
каждой линии эмиссии ветви (ENSDF/LNHB, выход ≥2 % на распад нуклида
либо все известные линии переключением) сопоставляется не эффективность
пика, а весь депонированный спектр монохроматического кванта этой
энергии (пик + комптоновский континуум + все вторичные процессы),
снятый на 24-узловой моноэнергетической сетке того же объёмного
источника. Суммы таких откликов подгоняются одной амплитудой ко всему
спектру. Отдельно учтены подтверждённые сумм-пики каскадного совпадения
и K-рентген дочерних. Есть разложение по 11 каналам взаимодействия
(фотоэффект/комптон с вылетом или без/рождение пар/вылет рентгена или
тормозного/вторичные извне) — тот же классификатор, что в
AtomSpectra Nano 16 PRO. Тот же переключатель утечки торона, что у
метода 1.

**Калибровка** — откалиброванные спектры образца и фона с реперными
γ-линиями, и отдельно калибровка приборного разрешения (ПШПВ) по этому
же спектру.

**Сравнение** — паспорт против двух оценок активности на одной шкале,
интервалы неопределённости — цветные полоски.

## Сборка

```
python export_data.py            # прогон → g1s_th232_data.json
python build_page.py             # шаблон + данные → dist/ и один файл
```

Нужны переменные окружения `G4MODELS_BUILD_GAMMA_1S` (каталог сборки
Geant4-модели, см. ниже) и `PYTHONIOENCODING=utf-8`.

Выход:

| путь | назначение |
|---|---|
| `dist/index.html` + `dist/styles/` + `dist/scripts/` + `dist/data.js` | раздельные файлы, для статического хостинга |
| `g1s_th232.html` | то же одним файлом, для площадок, принимающих один файл |

`dist/`, `g1s_th232_data.json` и `g1s_th232.html` не коммитятся —
производные, пересобираются одной командой.

## Требуемые входы

- **Спектр Th-232 в маринелли (BecqMoni XML):** `Th232_420-7-17_Маринелли_0cm.xml`
  в приватном SPECTRAVIBE_ROOT (`detectors/Gamma-1S/reference_spectra/
  reference_kits_becqmoni/Marinelli_1L/Th-232/`). В XML лежит и образец,
  и фон той же геометрии (`BackgroundEnergySpectrum`) — фон берётся
  оттуда, не из отдельного файла.
- **МК-шаблоны индивидуальных нуклидов ветви (метод 1):** восемь файлов
  `iso_<Nuc>.csv` в `G4MODELS_BUILD_GAMMA_1S`. Каждый прогон ограничен
  одним нуклидом через `nucleusLimits`, чтобы дочерние не примешивались.
  Число распадов своё на каждое звено (200 тыс.–3 млн — слабая
  гамма-ветвь требует на порядки больше статистики, R66) — задано в
  `configs/th232.yaml` (`geant4.isotope_runs`), макрос
  `../macros/decay_th232_isotopes.mac` из него генерируется:
  `python ../tools/generate_isotope_macro.py`. Руками макрос не
  редактировать — правки потеряются при следующей генерации.
- **Моноэнергетическая сетка (метод 2):** 24 файла `grid/rho1.60_E*.csv`
  (полный депонированный спектр, гамма-первичная) + парные
  `grid/rho1.60_E*_chan.csv` (то же разложенное по 11 каналам
  взаимодействия — нужен инструментированный exe, собранный из
  `../geometry/main.cc`).
- **Полная библиотека линий ветви:** `data/ensdf_th232_chain_lines.csv`
  (выгрузка ENSDF через IAEA Live Chart of Nuclides) — коммитится вместе
  со страницей, отдельно не генерируется этим конвейером.

## Правила, встроенные в конвейер

Числа в прозе **не набираются руками**. В разметке стоят метки вида
`{{apass}}`, `{{m2_nlines}}`, `{{fw_k}}`; значения подставляются при
сборке из выгрузки. Сборка отказывается собирать, если:

- нераскрытая метка встретилась в разметке;
- в тексте разметки есть доля в процентах или отношение, набранные
  цифрами (сторож против ручного набора чисел расчёта — ловил себя на
  этом же несколько раз в ходе разработки);
- секрет-скан нашёл локальный путь, адрес почты или токен GitHub.

Сторожа проходят самопроверку на заведомо грязной строке.

## Оформление

Плакатное: рама 3 px + тень 7×7 px без размытия вокруг всей страницы,
тяжёлый гротеск, жёлтая плашка `#f6d31c` как единственный акцент. Весь
прозаический текст — по ширине (`text-align: justify`). Цвета нуклидов
и каналов взаимодействия заданы в самой выгрузке.

## Известная систематика

Оба метода систематически дают активность ниже паспорта (метод 1 —
на ~16 %, метод 2 — на ~17–20 % в зависимости от состава библиотеки).
Причина — не в алгоритме разбора, а в модели маринелли-1 л: расчётная
эффективность в этой геометрии выше измеренной на аттестационной
кривой того же прибора. Для настоящей страницы важно, что **оба метода
при одной и той же модели дают согласующиеся между собой числа** —
вклад алгоритма меньше вклада модели.

Отдельная находка (не разобрана): оценка доли утечки торона (η) сильно
расходится между методом 1 (~5 %) и методом 2 (от ~1 до ~18 % в
зависимости от состава библиотеки) — расхождение указывает на
чувствительность двухпараметрической подгонки к полноте модели, а не
обязательно на реальную физику утечки такого масштаба.
