## §3. Архитектура: 4 независимые группы, не цепочка

Ключевое отличие от Th-232/Ra-226: источник — искусственная смесь 4
НЕ связанных распадом нуклидов. `configs/amticseu.yaml` вводит
`nuclides[].group` (= key), `passport.components` (4 записи вместо
одной). `export_amticseu_data.py` (форк `export_ra226_data.py`,
переиспользует `read_pair`/`run_method2`/`factory_fwhm_keV` оттуда как
уже нуклид-агностичные) считает МЕТОД 1 и МЕТОД 2 каждый с 4 НЕЗАВИСИМЫМИ
свободными амплитудами (+ фон), не с одной общей — то же обобщение,
которое `export_ra226_data.py` уже применял как ДИАГНОСТИЧЕСКИЙ разрез
(`radon_check`), здесь оно основная модель.

`tools/generate_isotope_macro.py` расширен полем `z_min`/`z_max`
(опционально, по умолчанию = z) — нужно для Ti-44: nucleusLimits(44,44,
20,22) захватывает ВЕСЬ каскад Ti-44→Sc-44→Ca-44 (67,868/78,323 кэВ
Ti-44-own + 1157,022 кэВ и аннигиляция Sc-44) в ОДНОМ Geant4-прогоне —
единственный способ получить Sc-44's собственный распад (иначе
nucleusLimits с одним Z заморозил бы Sc-44 как «стабильный»). Am-241 —
СОЗНАТЕЛЬНО НЕ Z-диапазон (единственный Z=95) — иначе дочерний Np-237
(T½=2,14 млн лет) распался бы в модели из-за
`thresholdForVeryLongDecayTime`, чего в 24-летнем источнике нет.
Cs-137 использует уже существующий `excitation_keV` (спавнит Ba-137m
напрямую, E*=661,659 кэВ), `br=0,9457` (доля заселения — ✅ ПРЯМАЯ
цитата LNHB Pγ+ce, см. §5) домножается программно.

n_events: Am241 1М, Ti44chain 1М, Cs137chain 500К, Eu152 2М (по силе
слабейшей нужной линии). Ti44chain-прогон занял АНОМАЛЬНО долго (~50
минут CPU против ~5 минут у Am241 при том же n_events) — вероятно,
построение физтаблиц для расширенного Z-диапазона иона (20-22)
дороже, чем для одиночного Z; CPU оставался активным (не завис),
итог корректный (SHIELD/COINC-строки в логе разумны).

## §6. Результат прогона (e_lo_kev=40, e_hi_kev=1500)

```
метод 1 (4 независимые амплитуды): chi2/ndof=27.56
  Am241        A=7406.8±117.3 Бк  ratio=1.804
  Ti44chain    A=1746.9±7.2 Бк  ratio=0.966
  Cs137chain   A=1865.3±15.7 Бк  ratio=1.165
  Eu152        A=2387.4±16.3 Бк  ratio=1.179
метод 2 (F_B/TCS, 4 независимые амплитуды): chi2/ndof=44.34
  Am241        A=11487.4±112.5 Бк  ratio=2.797
  Ti44chain    A=1486.8±6.5 Бк  ratio=0.823
  Cs137chain   A=1845.9±15.4 Бк  ratio=1.153
  Eu152        A=2187.9±15.6 Бк  ratio=1.081
```

**Диагностика χ²/ν по полосам — ИСПРАВЛЕНА 11.08.2026 (находка Б1
внешнего адверсариального аудита, БЛОКИРУЮЩАЯ).** Первый заход (числа
ниже, ЗАЧЕРКНУТЫ по смыслу, оставлены для истории ошибки) смешал ДВЕ
разные формулы χ²: заявленный «≈24 700 в 40–90 кэВ» посчитан по
ЧИСТОЙ пуассоновской σ=√max(y,1) — эта величина НЕ суммируется в
заявленный итоговый χ²=13367,9/21505,2 (реально даёт 477425 — на
порядок больше), а `fit_amplitudes` (export_data.py) считает итоговый
χ² по σ ВТОРОГО прохода NNLS (с систематическим полом
`SYS_FLOOR=0,03`, зависящим от МОДЕЛИ первого прохода, не финальной).
Аудитор восстановил формулу побитово (совпадение chi2 с JSON до
10+ значащих цифр) и пересчитал полосы ПРАВИЛЬНО:

| полоса, кэВ | доля от χ² метод 1 (27,6) | доля от χ² метод 2 (44,3) |
|---|---|---|
| 40–90 | 36,4% | 40,3% |
| 90–200 | 11,3% | 13,6% |
| 200–500 | 15,4% | 18,9% |
| 500–1000 | 9,2% | 5,7% |
| 1000–1500 | 27,6% | 21,4% |

40–90 кэВ — крупнейший вклад, но НЕ «практически весь»: полоса
1000–1500 кэВ (главная линия Sc-44 1157,02 + три сумм-пика Eu-152 —
1085,84/1112,08/1123,18/1233,86) даёт почти столько же. Формулировка
«Ti-44/Cs-137/Eu-152 не затронуты, потому что вся проблема в 40–90
кэВ» — НЕ подтверждена той же метрикой, которой посчитан заявленный
χ²/ν, и снята со страницы. Реальное основание оговорки по Am-241 —
расхождение ДВУХ НЕЗАВИСИМЫХ МЕТОДОВ на 55% (7407 vs 11487 Бк,
Ti-44/Cs-137/Eu-152 сходятся заметно теснее — 14,9–17,5%/~1%/~9%),
не χ²-полоса. Повышенный χ²/ν (27,6/44,3) — свойство модели в целом
(везде плохо в разной степени), см. `sci-search`-урок: не путать
разные определения одной и той же величины (σ первого/второго
прохода) при построении собственной диагностики — тот же класс
ошибки, что citation-green, только внутри своего же кода.

**Диагностический прогон** (e_lo_kev=90, ОТМЕНЁН, не в конфиге): Am-241
теряет единственную линию из окна подгонки → столбец Am-241 вырожден
(все нули в `sel`) → NaN в ковариации → `json.dump(allow_nan=False)`
падает громко, как задумано гвардом. Подтверждает: полоса 40–90 кэВ
НЕОБХОДИМА для Am-241, но модель её не тянет — компромисса без
дополнительной физики (ХРИ защиты отдельной сущностью, энергошкала как
параметр — методика `analysis/mix_unfold.py`, более раннего проекта по
этому же комплекту) нет.

**Решение**: e_lo_kev=40 оставлен (нужен и для Ti-44). Am-241
опубликован с явной, видной оговоркой «результат формального фита, не
достоверная оценка» — на вкладке «сравнение» и в попапе «как
посчитано». Ti-44/Cs-137/Eu-152 — обычная публикация, как на Th-232/
Ra-226.
