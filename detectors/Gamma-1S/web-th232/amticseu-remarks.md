## §3. Архитектура: 4 независимые группы, не цепочка

Ключевое отличие от Th-232/Ra-226: источник — искусственная смесь 4
НЕ связанных распадом нуклидов. `configs/amticseu.yaml` вводит
`nuclides[].group` (= key), `passport.components` (4 записи вместо
одной). `export_amticseu_data.py` (форк `export_ra226_data.py`,
переиспользует `read_pair`/`run_method2`/`factory_fwhm_keV` оттуда как
уже нуклид-агностичные) считает МЕТОД 1 и МЕТОД 2 каждый с 4 НЕЗАВИСИМЫМИ
свободными амплитудами (+ фон), не с одной общей — то же обобщение,
которое `export_ra226_data.py` уже применял как ДИАГНОСТИЧЕСКИЙ разрез
(`radon_check`), здесь оно основная модель.

`tools/generate_isotope_macro.py` расширен полем `z_min`/`z_max`
(опционально, по умолчанию = z) — нужно для Ti-44: nucleusLimits(44,44,
20,22) захватывает ВЕСЬ каскад Ti-44→Sc-44→Ca-44 (67,868/78,323 кэВ
Ti-44-own + 1157,022 кэВ и аннигиляция Sc-44) в ОДНОМ Geant4-прогоне —
единственный способ получить Sc-44's собственный распад (иначе
nucleusLimits с одним Z заморозил бы Sc-44 как «стабильный»). Am-241 —
СОЗНАТЕЛЬНО НЕ Z-диапазон (единственный Z=95) — иначе дочерний Np-237
(T½=2,14 млн лет) распался бы в модели из-за
`thresholdForVeryLongDecayTime`, чего в 24-летнем источнике нет.
Cs-137 использует уже существующий `excitation_keV` (спавнит Ba-137m
напрямую, E*=661,659 кэВ), `br=0,9457` (доля заселения — ✅ ПРЯМАЯ
цитата LNHB Pγ+ce, см. §5) домножается программно.

n_events: Am241 1М, Ti44chain 1М, Cs137chain 500К, Eu152 2М (по силе
слабейшей нужной линии). Ti44chain-прогон занял АНОМАЛЬНО долго (~50
минут CPU против ~5 минут у Am241 при том же n_events) — вероятно,
построение физтаблиц для расширенного Z-диапазона иона (20-22)
дороже, чем для одиночного Z; CPU оставался активным (не завис),
итог корректный (SHIELD/COINC-строки в логе разумны).

## §6. Результат прогона (e_lo_kev=40, e_hi_kev=1500)

```
метод 1 (4 независимые амплитуды): chi2/ndof=27.56
  Am241        A=7406.8±117.3 Бк  ratio=1.804
  Ti44chain    A=1746.9±7.2 Бк  ratio=0.966
  Cs137chain   A=1865.3±15.7 Бк  ratio=1.165
  Eu152        A=2387.4±16.3 Бк  ratio=1.179
метод 2 (F_B/TCS, 4 независимые амплитуды): chi2/ndof=44.34
  Am241        A=11487.4±112.5 Бк  ratio=2.797
  Ti44chain    A=1486.8±6.5 Бк  ratio=0.823
  Cs137chain   A=1845.9±15.4 Бк  ratio=1.153
  Eu152        A=2187.9±15.6 Бк  ratio=1.081
```

**Диагностика χ²/ν по полосам — ИСПРАВЛЕНА 11.08.2026 (находка Б1
внешнего адверсариального аудита, БЛОКИРУЮЩАЯ).** Первый заход (числа
ниже, ЗАЧЕРКНУТЫ по смыслу, оставлены для истории ошибки) смешал ДВЕ
разные формулы χ²: заявленный «≈24 700 в 40–90 кэВ» посчитан по
ЧИСТОЙ пуассоновской σ=√max(y,1) — эта величина НЕ суммируется в
заявленный итоговый χ²=13367,9/21505,2 (реально даёт 477425 — на
порядок больше), а `fit_amplitudes` (export_data.py) считает итоговый
χ² по σ ВТОРОГО прохода NNLS (с систематическим полом
`SYS_FLOOR=0,03`, зависящим от МОДЕЛИ первого прохода, не финальной).
Аудитор восстановил формулу побитово (совпадение chi2 с JSON до
10+ значащих цифр) и пересчитал полосы ПРАВИЛЬНО:

| полоса, кэВ | доля от χ² метод 1 (27,6) | доля от χ² метод 2 (44,3) |
|---|---|---|
| 40–90 | 36,4% | 40,3% |
| 90–200 | 11,3% | 13,6% |
| 200–500 | 15,4% | 18,9% |
| 500–1000 | 9,2% | 5,7% |
| 1000–1500 | 27,6% | 21,4% |

40–90 кэВ — крупнейший вклад, но НЕ «практически весь»: полоса
1000–1500 кэВ (главная линия Sc-44 1157,02 + три сумм-пика Eu-152 —
1085,84/1112,08/1123,18/1233,86) даёт почти столько же. Формулировка
«Ti-44/Cs-137/Eu-152 не затронуты, потому что вся проблема в 40–90
кэВ» — НЕ подтверждена той же метрикой, которой посчитан заявленный
χ²/ν, и снята со страницы. Реальное основание оговорки по Am-241 —
расхождение ДВУХ НЕЗАВИСИМЫХ МЕТОДОВ на 55% (7407 vs 11487 Бк,
Ti-44/Cs-137/Eu-152 сходятся заметно теснее — 14,9–17,5%/~1%/~9%),
не χ²-полоса. Повышенный χ²/ν (27,6/44,3) — свойство модели в целом
(везде плохо в разной степени), см. `sci-search`-урок: не путать
разные определения одной и той же величины (σ первого/второго
прохода) при построении собственной диагностики — тот же класс
ошибки, что citation-green, только внутри своего же кода.

**Диагностический прогон** (e_lo_kev=90, ОТМЕНЁН, не в конфиге): Am-241
теряет единственную линию из окна подгонки → столбец Am-241 вырожден
(все нули в `sel`) → NaN в ковариации → `json.dump(allow_nan=False)`
падает громко, как задумано гвардом. Подтверждает: полоса 40–90 кэВ
НЕОБХОДИМА для Am-241, но модель её не тянет — компромисса без
дополнительной физики (ХРИ защиты отдельной сущностью, энергошкала как
параметр — методика `analysis/mix_unfold.py`, более раннего проекта по
этому же комплекту) нет.

**Решение**: e_lo_kev=40 оставлен (нужен и для Ti-44). Am-241
опубликован с явной, видной оговоркой «результат формального фита, не
достоверная оценка» — на вкладке «сравнение» и в попапе «как
посчитано». Ti-44/Cs-137/Eu-152 — обычная публикация, как на Th-232/
Ra-226.

Обе правки проверены в браузере (localhost, JS-исполнение) —

## §11. Замечание №8 — деконволюция мультиплетов, калибровка (11.08.2026)

Директива оператора: «правь калибровку. примени деконволюцию и
откалибруй по пикам из мультиплетов». Разбор — три попытки, третья
принята.

**Попытка 1: ступенчатая подложка в `fit_peak_multiplet`.** Гипотеза —
подложка ПРЯМОЙ линией под пиком в NaI (`export_data.py:_multiplet_chi2`)
даёт занижённый центроид (урок Ra-226, файл -19, ra226-remarks.md §16).
Заменена на erfc-ступень (модель Debertin/Helmer). На 6 якорях Th-232
(слитно с наклоном) — не хуже нигде, лучше на 3 из 6 (χ² сумма 19,9→
15,9). Но задачу НЕ решила: на AmTiCsEu чистые линии 661,657/1408,013
кэВ (chi2/ndof 1,9/1,25 — статистически хороший фит) дали сдвиг
−3,2/−10,9 кэВ при независимо подтверждённой шкале ≤1,1 кэВ там же —
метод уверенно ошибается, не только на плохих фитах. Оператор показал
скриншот оригинала SpectraLine: подложка там тоже БЕЗ ступени, гладкая
наклонная. Ступень ОТКАЧЕНА целиком (без выигрыша в задаче отклоняться
от эталонной методологии не оправдано) — `export_data.py` вернулся к
исходному наклону, докстринг `_multiplet_chi2` несёт итог попытки.

**Попытка 2: деконволюция без ступени, поиск якоря по мультиплетам.**
На чистой линии 1408,013 сдвиг ушёл почти в ноль (−0,10 кэВ, было
−10,9 со ступенью) — переусложнение модели действительно уводило фит
от истины при формально лучшем χ². Но окно Sc-44 (1157,02) осталось
неустойчивым: без учёта соседей деконволюция ОБНУЛЯЕТ саму линию
(`amp_anchor=0`), счёт объясняется тремя соседними линиями Eu-152
(1085,8/1089,7/1112,1) — картинка (4 окна, отправлена оператору)
показала это наглядно: красная гауссиана-якорь у Sc-44 не поднимается
над нулём, пик тянут голубые пунктиры соседей. Тот же класс сбоя, что
уже задокументирован для 300,087/860,557 кэВ Th-232 (FWHM_ANCHORS,
export_data.py) — тесно расположенные линии при сравнимой с их
разносом ширине дают вырожденную NNLS-подгонку.

**Попытка 3 (принята): якорь Am-241, локальная поправка по образцу
Ra-226.** Оператор прислал 2 скриншота декомпозиции ОРИГИНАЛА
SpectraLine для узла 40-90 кэВ: Am-241 читается на 54,32/54,63 кэВ (два
захвата), Ti-44/Sc-44 в узле 1000-1400 — практически на номинале
(1151-1156 против 1157,02, скриншот декомпозиции того узла отдельно) —
значит заявленный ранее "сдвиг Sc-44 на 10 кэВ" (§10, измеренный
максимум ≈1146) сам, вероятно, артефакт argmax на блендированном
максимуме композита, а НЕ ошибка шкалы: у собственной, более аккуратной
декомпозиции вендора та же линия садится у номинала.

Для Am-241 — наоборот, реальный локальный сдвиг, подтверждённый ДВУМЯ
независимыми методами В КАНАЛЬНОМ пространстве (не только в кэВ, где
случайное совпадение калибровок само по себе могло бы всё объяснить):
argmax по фон-вычтенным отсчётам с параболическим уточнением вершины
(окно ~0,55×ПШПВ, не наивные ±10 кэВ — та же наивная ширина окна на
964,057 давала ложный уход −12,7 кэВ, отброшено) даёт канал 24,0-24,16;
обратный пересчёт вендорских 54,32/54,63 кэВ через ТУ ЖЕ заводскую
квадратику даёт канал 24,49-24,60. Разброс <0,6 канала ≈1,5 кэВ —
методы видят один и тот же канал. Взят якорь: канал 24,3 → истинная
энергия 59,541 кэВ.

Оператор в этот момент снял директиву Ra-226 «сам не калибруй» —
явная отмена, зафиксировать как действующую на будущее для этой и
смежных линий.

Поправка: квадратика (3 коэффициента) через 5 точек — 1 новая (канал
24,3 → 59,541 кэВ) + 4 уже подтверждённых заводских (344,279/511,0/
661,657/964,057 кэВ, канал взят ОБРАТНЫМ пересчётом заводской
квадратики, не собственным argmax — на слабых линиях у argmax свой
систематический перекос от континуума соседних сильных линий, см.
выше). Невязка рефита на всех 5 точках <1,2 кэВ. Экстраполяция
квадратики за пределы анкеров расходится с заводской (как и у Ra-226:
+18 кэВ на канале 600, +89 на 1023) — поэтому поправка сшита
smoothstep-переходом с заводской в полосе каналов 60-150 и уходит в
ноль выше; заводская шкала выше канала 150 (~425 кэВ) не тронута.
Реализация — `export_amticseu_data.py`, `_apply_am241_anchor_correction`
внутри `main()` (самодостаточная функция, не требует правок в
`export_data.py`/`export_ra226_data.py`). Фон НЕ поправлен — вклад фона
в полосу 40-90 кэВ пренебрежим (~100-160 отсчётов против ~130000 net
у образца, <0,15%), да и якоря там физически нет (источник при наборе
фона отсутствовал).

**Результат.** χ²/ν упал вдвое: метод 1 27,6→14,9; метод 2 (отобр.)
33,5→22,9. Am-241/паспорт: 1,80×→1,30× (метод 1) / 1,39× (метод 2).
Согласие МЕЖДУ методами ухудшилось (0,7%→6,8%) — ожидаемо и честно:
прежние 0,7% были совпадением НА общей систематической ошибке шкалы у
обоих методов, не независимым согласием. Остаточное завышение (30-39%)
над паспортом — по-видимому реальная систематика источника или модели
самопоглощения мягкой линии в матрице с 20% кальция, не артефакт
калибровки. Текст страницы (интро, вкладка «сравнение», вкладка
«калибровка», попап «как посчитано») переписан под новые числа во всех
местах.

**Урок для skill.md.** Наивный argmax/деконволюция с окном УЖЕ ПШПВ на
энергии (не заметно шире) даёт ложные сдвиги на слабых/блендированных
линиях — решает НЕ форма подложки (проверено и отброшено), а (1)
достаточная ширина окна (≥0,5×ПШПВ) и (2) независимое подтверждение
канала ВТОРЫМ методом, желательно внешним (эталонное ПО, вендорская
таблица пиков), прежде чем доверять числу как якорю калибровки.

## §13. Поправка шкалы ФОНА — 11-якорный рефит (11.08.2026, замечание «фон не откалиброван»)

Заводская калибровка фона (линейная, 2 коэффициента) отдельная от
образца и не была затронута поправкой Am-241 (§11, scoped к образцу).

**Первая попытка (отклонена оператором).** Одноточечная проверка по
K-40 (1460,822 кэВ) с наивным окном 1350-1560 кэВ дала взвешенный
центроид 1444,46 кэВ (сдвиг −16,36 кэВ). Применена как сдвиг ТОЛЬКО
нуля (константы), наклон заводским — по прецеденту фона Ra-226
(`apply_xray_anchor_correction_bg`, ra226-remarks.md §16). Оператор
отклонил прямо: «просто двигать - ошибка!!!». Причина ошибки
вскрылась при перепроверке: окно 1350-1560 кэВ шире истинной ПШПВ
прибора на этой энергии в ~2 раза — центроид ушёл в структуру
континуума, дав завышенный по модулю ложный сдвиг (та же ошибка уже
ловилась в этой сессии на образце, якорь 964,057 кэВ).

**Финальная методика.** По указанию применить методику SpectraVibe
(`references/01_metadata_calibration.md`, «Background-only anchor
heuristic») — 10 природных линий ЕРН/фона NaI (Pb-212/214 238,63,
Pb-214 295,21/351,93, Tl-208+аннигиляция 511,0, Bi-214
609,32/1120,29/1764,49, Ac-228 911,20, K-40 1460,822, Tl-208 2614,511),
каждая с окном 0,6×ПШПВ прибора (не наивные широкие окна), линейной
подложкой по краям окна и взвешенным (вес~√чистый счёт) центроидом в
КАНАЛЬНОМ пространстве (не в кэВ — не зависит от уже неверной заводской
шкалы). Дополнительно, по прямому указанию оператора («и ХРИ свинца
защиты на фоне есть. и 238 тория. Всегда проверяй и используй») —
проверен К-рентген Pb защиты: физика подтверждена IAEA (Bi-207
EC→Pb-207), интенсивностно-взвешенное среднее кластера Kα1/Kα2/Kβ1/Kβ2
= 76,66 кэВ, но взвешенный центроид в ЭТОМ фоне НЕ сходится с шириной
окна (75,88 → 72,39 → 71,09 → 69,46 → 69,36 кэВ при окнах ±5,8…±25 кэВ)
— по статистике якорь не прошёл бы отбор. Оператор указал прямо:
«просто прими для ХРИ свинца защиты 77» (тот же приём, что якорь
Ra-226 §16 — округлённое табличное значение вместо нестабильного
измеренного). Принят как 11-й якорь: E=77,0 кэВ, канал=34,0 (argmax в
узком окне вокруг факторного предсказания канала, не по недостоверному
центроиду), netsum=77,2 (наименьший из 11 — соответственно наименьший
вес в МНК).

Итоговая взвешенная МНК-подгонка (channel, true_keV) по всем 11 точкам
— линейная (degree=1): `coefs_new=[-20.469, 2.9862]` против заводских

кривизны ~1e-5 физически не обоснован — детектор NaI линеен в этом
диапазоне, малое улучшение объясняется переобучением на единственный

(`export_amticseu_data.py`, `_BG_ANCHORS_*`) — поправка сквозная: меняет
вычитаемый фон в net-спектре, на вкладке «калибровка», везде, где
используется `spectrum.bg_counts`. Воспроизводимо:
`analysis/bg_seven_line_anchor_check.py` (заменяет устаревший

Эффект на итоговые числа малый (фон везде мал относительно сигнала,
кроме высокоэнергетичного хвоста), относительно отклонённой

везде улучшение, не ухудшение, несмотря на статистически слабый 11-й
якорь.

## §14. Жёлтая панель (грouptable + χ²/ν) — три доводки по скриншотам (11.08.2026)

Три отдельных замечания оператора по одной и той же панели (таблица
групп + χ²/ν-бокс справа), каждое со своим скриншотом:

1. **Вложенная рамка.** `.grouprow > .summary` (χ²/ν-бокс) нёс класс
   `.summary` целиком и наследовал ПОЛНОЕ оформление панели (рамка 2px
   + тень + жёлтый фон) от базового правила — рамка внутри рамки, тень
   внутри тени. Снято явно (`border:none; box-shadow:none;
   background:transparent`) для вложенного случая (специфичность
   `.grouprow>.summary` выше базового `.summary`).
2. **Высота бокса.** После снятия рамки бокс остался растянут на ПОЛНУЮ
   высоту `.grouptable-wrap` (`align-items:stretch`) — включая шапку
   таблицы, а не только тело: верх бокса не совпадал с чёрной линией
   под шапкой, контент кучковался у верха с пустым хвостом снизу.
   `margin-top` = измеренная высота зоны шапки (2,55rem) — flexbox
   вычитает margin из stretch-высоты САМ, верх съезжает точно на чёрную
   линию, низ не трогается (=низ таблицы). `justify-content:
   space-between` разносит 2-3 строки статистики по всей высоте.
   Проверено live DOM (getBoundingClientRect): верх бокса = низ шапки
   (746,4 vs 746,5), низ бокса = низ таблицы (905,9 vs 905,9) на
   методе 1; то же на методе 2 с 3 строками.
3. **Центрирование столбца «против паспорта».** Значения были прижаты
   к левому краю широкого столбца, хотя заголовок столбца — по центру
   (`table.big td:last-child{text-align:left}` — общее правило для
   столбцов-примечаний, здесь неуместно). Тот же приём, что уже
   применялся для `.ratio-cell` (cmpTable, §12) и `#tblM2` — добавлен
   класс `ratio-cell` последней `<td>` в `groupTable()`
   (`g1s-amticseu.js`), готовое правило `table.big td.ratio-cell
   {text-align:center}` подхватило без новой CSS.

Общий `styles/g1s-th232.css` (амтисеу/ra226/th232) — затронуты пп. 1-2;
th232/ra226 не используют `.grouprow`, эффекта на них нет (проверено
grep по их HTML). Проверка велась через локальный http.server +
DOM-запросы (getBoundingClientRect/getComputedStyle), не через
screenshot — панель Browser не отображается пользователю в этом
окружении (тот же ограничитель, что и раньше в сессии).
