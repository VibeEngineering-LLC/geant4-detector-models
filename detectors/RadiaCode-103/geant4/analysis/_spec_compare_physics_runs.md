- `ftc.BANDS` — СПИСОК пар `(e1, e2)` в кэВ, например `[(20,100),(100,300),...]`. Это список кортежей, не словарь.

# Поведение
1. Загрузить base. Если в `meta` нет ключа `em_cut_mm` или `em_deex` — напечатать «ОТКАЗ: <путь> не содержит em_cut_mm/em_deex — старый формат CSV, физика прогона не записана» и выйти с кодом 2. То же для каждого test.
2. Для каждого test проверить, что значения ключей `shield`, `stand_mm`, `screen_up`, `n_events`, `flux_total_cm2_s` в `meta` совпадают с base (сравнение `!=`; отсутствующий ключ = None). При любом расхождении напечатать по строке на ключ «ОТКАЗ: постановки различаются по '<ключ>': base=<v> vs <имя файла test>=<v>» и выйти с кодом 2. Смысл: сравнение двух постановок обязано различаться ровно одной вещью.
3. Для каждого test напечатать заголовок вида `=== <имя файла>: em_cut_mm <base>→<test>, em_deex <base>→<test> ===`, строку `hits base=<n_hits_in_crystal base> test=<... test>` (целые), затем таблицу по полосам `list(ftc.BANDS) + [(20, 2999)]`: колонки «полоса, кэВ», `c_base` (сумма counts base в [e1, e2)), `c_test`, `test/base` (отношение СУММ cps в полосе, 4 знака), `±` (абсолютная ошибка `ratio*sqrt(1/c_base + 1/c_test)`, 4 знака). Если `c_base < 100` или `c_test < 100` — дописать в строку «  (мало статистики)». Если сумма cps base в полосе равна 0 — ratio = inf, ошибка = inf.
4. Код возврата 0.
