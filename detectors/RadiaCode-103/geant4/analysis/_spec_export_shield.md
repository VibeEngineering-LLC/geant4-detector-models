# Что считать

Всё через уже готовые функции модулей `ps` и `ds` — своей реализации чтения,
свёртки, ремешка и подгонки НЕ писать.

1. `amp_map, names = ds.fit_open()` — исходные активности из открытого фона.
2. `acts = ds.nuclide_activities(amp_map)`.
3. Открытый фон: `cnt_o, e_o, live_o, _ = ps.read_meas(ftc.MEAS_NAME, ftc.CAL_ROOM)`,
   отбор `sel_o = (e_o >= ftc.E_LO) & (e_o < ftc.E_HI)`.
4. Домик: `cnt_s, e_s, live_s, cal_s = ps.read_meas(ps.MEAS_SHIELD, None)`,
   отбор `sel_s`. Калибровку `cal_s` выгрузить — она приборная, из файла.
5. Понуклидные вклады в домике:
   `parts = ds.per_nuclide_spectra(ps.FMT_SHIELD, ps.MUON_SHIELD_CSV, e_s[sel_s], acts)`.
   Полная модель — сумма по всем ключам.
6. Пропускание: `T = ds.transmission(e_s[sel_s])`.
7. Модель открытого фона — нужна для таблицы ослабления. Считается так же, как
   в `ds.fit_open`, но там она не возвращается, поэтому пересчитать здесь:
   `parts_open = ds.per_nuclide_spectra(ps.FMT_OPEN, ftc.MUON_CSV, e_o[sel_o], acts)`,
   полная модель открытого фона — сумма по ключам.

# Разделение по происхождению

Шаблоны с домиком, посчитанные после 29.08.2026, содержат ДОПОЛНИТЕЛЬНЫЕ колонки
`counts_direct`, `counts_pb_scat`, `counts_pb_born` — счёт, разделённый по тому,
дошёл ли фотон до кристалла мимо свинца, прошёл сквозь него с рассеянием, либо
родился в нём (флуоресценция K-серии, тормозное).

⚠ `ftc.read_template` читает только три первые колонки и о новых не знает —
трогать его НЕЛЬЗЯ, на нём держится весь остальной разбор. Напиши в этом файле
отдельную функцию `read_origin(path)`:

- читает файл построчно, находит строку-заголовок, начинающуюся с `bin_keV`;
- если в заголовке меньше шести колонок — возвращает `None` (шаблон старый,
  разделения в нём нет; это НЕ ошибка, вкладка обязана работать и без него);
- иначе возвращает словарь `{"direct": массив, "pb_scat": массив, "pb_born": массив}`
  длиной как гистограмма, значения — сырые отсчёты МК (колонки 4, 5, 6);
- дополнительно вернуть `t_run_s` из метаданных, он нужен для перевода в cps.

Дальше для каждого нуклида: если `read_origin` вернул данные, поделить каждую
из трёх категорий на `t_run_s` (получив cps на 1 Бк/кг), свернуть
`ftc.rcspec.fold(..., "103", tail_T=ps.TAIL_T)`, перевести на сетку измерения
`ps.to_meas_grid` и домножить на активность нуклида. Просуммировать по всем
нуклидам — получатся три ряда: `origin_direct`, `origin_pb_scat`, `origin_pb_born`
в имп/с на сетке домика.

Мюоны в это разделение НЕ входят: их шаблон считает другая программа, колонок
происхождения в нём нет. Выгрузить их отдельным рядом `origin_muon` (это уже
готовый `parts["mu"]`), и в JSON поставить флаг `has_origin` — правда только
если разделение прочиталось у ВСЕХ восьми нуклидов.

# Таблицы

`bands` — список по `ftc.BANDS`, каждый элемент:
```
{"lo":…, "hi":…,
 "meas":   измерение в домике, имп/с,
 "model":  модель в домике, имп/с,
 "ratio":  model/meas,
 "att_meas":  ослабление по измерению (открытый фон / домик),
 "att_model": ослабление по модели,
 "frac": {имя: доля нуклида в модели этой полосы, проценты}}
```
⚠ Суммы для открытого фона и для домика считать каждую на СВОЕЙ энергетической
сетке (`e_o[sel_o]` и `e_s[sel_s]`) — калибровки у двух измерений разные.
Отношения считать ДО округления.

`pbk` — таблица вокруг K-линий свинца, по интервалам
`[(40,60),(60,70),(70,80),(80,90),(90,100),(100,120),(120,160)]`, поля
`lo`, `hi`, `meas`, `model`, `ratio`. Эта таблица показывает, что модель
недобирает именно на линиях флуоресценции.

`contrib` — интегральный вклад каждой компоненты: список
`{"name":…, "cps":…, "pct":…}`, отсортированный по убыванию.

# Структура JSON

```
{
 "meas_shield": {"file","live_s","live_h","live_d","total_counts","cps","cal":[3 числа]},
 "meas_open":   {"live_s","live_h","cps"},
 "energy":  прореженная сетка домика,
 "measured": прореженное измерение в домике, имп/с,
 "model":    прореженная полная модель, имп/с,
 "parts":    {имя: прореженный ряд},
 "trans":    {имя: прореженный ряд T(E); nan заменить на null},
 "origin":   {"direct":…, "pb_scat":…, "pb_born":…, "muon":…} — прореженные ряды,
 "has_origin": true/false,
 "acts": {имя: активность},
 "muon": {"amp":…, "pdg":…, "ratio":…},
 "setup": {"pb_mm":50, "cavity":"150x150x385", "top_open":true,
           "tail_T":…, "f_rn":…, "r_th":…, "f_tn":…},
 "chi2ndf": …, "shape": …,
 "bands": […], "pbk": […], "contrib": […],
 "ru": словарь русских имён (взять ds.RU)
}
```

Ряды прореживать как в образце: `idx = np.arange(0, len(e), STEP)`,
`ser = lambda v: [round(float(x), 8) for x in np.asarray(v)[idx]]`.
Для `trans` использовать вариант, заменяющий `nan` на `None`.
`chi2ndf`, `shape` — из `ftc.metrics(model_counts, meas_counts, 0)`, где
`model_counts = полная модель * live_s`, ноль параметров, потому что в
предсказании не подбиралось ни одного.

Запись: `os.makedirs` каталога `out`, `json.dump(..., ensure_ascii=False, separators=(",",":"))`.
В конце напечатать путь и размер файла в байтах.
