# Назначение

Разложение измеренного фона RC-103 с учётом (а) физического ВЕТВЛЕНИЯ — 8 нуклидных шаблонов сливаются в 3 амплитуды на голову цепочки (K-40 отдельно, Ra-226-цепочка = Pb-214+Bi-214, Th-232-цепочка = Ac-228+Pb-212+Bi-212+Tl-208/0.3594), (б) РАЗДЕЛЬНЫХ материалов — кирпич (стены) и бетон (перекрытия), каждая цепочка получает СВОЮ амплитуду в каждом материале, итого 6 амплитуд + мюоны = 7 неизвестных вместо прежних 8+1=9. Смысл: степень свободы «взаимная активность» (кирпич/бетон) заложена явно через раздельные шаблоны, а не постулируется общим множителем.

Docstring должен объяснить: слияние в цепочки — это ФИЗИКА (секулярное равновесие внутри цепочки между Rn-эманацией и коротким временем жизни промежуточных звеньев, см. литературный разбор в комментарии ниже), а не подгонка; branching factor 0.3594 — доля распадов Bi-212, идущая в Tl-208 (остальные 64.06% — альфа-канал в Po-212, без гамма). Упомянуть, что модуль переиспользует `fit_two_criteria` (импорт, не копия) для чтения шаблонов, свёртки разрешения, дисперсии и ядра NNLS-подгонки.

# Функция `load_chain_material(chain_name, material)`

Для цепочки и материала: для каждого нуклида в `CHAINS[chain_name][0]` строит путь `TEMPLATE_DIR/TEMPLATE_FMT % (material, нуклид)`. Если файла нет — печатает предупреждение с полным путём и пропускает (не падает). Через `ftc.read_template(path)` получает `(meta, arr, cnt_mc)`; вес нуклида — из `CHAINS[chain_name][1].get(нуклид, 1.0)`.

Складывает ВЗВЕШЕННО:
- `cps_sum += вес * ftc.rcspec.fold(arr, "103")` (свёрнутый с разрешением прибора вклад);
- `var_sum += (вес**2) * ftc.template_variance(cnt_mc, float(meta.get("t_run_s", 0.0)))` (дисперсия, уже свёрнутая внутри `template_variance`).

Возвращает `(cps_sum, var_sum)`, или `(None, None)`, если не найдено ни одного нуклида цепочки.
