# Geant4-модель RadiaCode-103

Комплект геометрии RC-103 для Monte Carlo (Geant4): корпус-envelope (примитив,
без STL), электроника, детектор.

**Обновлено 2026-08-26:** GDML впервые провалидирован штатным парсером Geant4
(`C:\geant4-gdml`, GDML-модуль появился в проекте в этот же день). Найден и
исправлен самоссылающийся материал `G4_Si` (P-001, `../audit/project-incidents.md`)
— до этой правки файл ни разу не проходил штатный парсер. После фикса прогнан
`G4PVPlacement::CheckOverlaps()` по всем physvol — результат и точные величины
протрузий см. «Ограничения модели» ниже.

**Обновлено 2026-08-26 (ночь): реальный `BeamOn` находил то, чего не находил
`CheckOverlaps()`.** При написании рабочего расчётного приложения (`geant4/run/`)
выяснилось, что `CheckOverlaps()` даёт только WARNING даже для physvol, ПОЛНОСТЬЮ
лежащего вне материнского объёма — а `G4SmartVoxelHeader::BuildNodes()` (строится
при `Initialize()`, ДО первого события) на этот же случай падает фатально. Рендер
никогда не доходит до `Initialize()`/`BeamOn`, поэтому дефект был невидим всем
сегодняшним более ранним проверкам. Исправлено (P-004, `../audit/project-incidents.md`)
— координаты `p_emi`/`p_disp_win`/`p_disp_lcd`/`p_usb` сдвинуты внутрь `Case_cavity`.
Мутационно проверено лично: на прежнем SSOT `BeamOn` падал (`PANIC`), на исправленном
— `EXIT=0`, 1M событий без единого fatal exception.

**Состав этого репозитория — только то, что реально написано/сгенерировано и
проверено ЗАПУСКОМ в этой сессии** (по прямому требованию оператора 26.08.2026:
«нужно оставить только твоё и проверенное», затем «оставить только твой
комплект, всё лишнее удалить»). Референсная папка оператора
(`D:\GoogleDrive\Дозиметрия\Спектры\RC103\geant4\`, локальная, вне репозитория)
содержит больше — STL-загрузчики (`cadmesh/`, требуют внешнюю библиотеку
CADMesh, которой на этой машине нет — не собирались), генератор тесселированных
GDML (`stl_to_gdml.py`), обмер по рентгену (`xray_measure.py`) и первый
verify-скрипт (`verify_align.py`, содержит найденный, но не исправленный
визуальный баг — легенда matplotlib перекрывает данные). Все прочитаны при
разборе, но НЕ собирались и не запускались в этой сессии — не перенесены.

## Рабочий расчётный комплект (`run/`, 26.08.2026)

Не только рендер — реальное Geant4-приложение с `BeamOn`. Загружает SSOT
напрямую через `G4GDMLParser` (паттерн `GdmlDetector`, `common/tools/gdml_vis.cc`
— C++-дублирование геометрии не потребовалось, как и у рендер-инструментов).
`PhysicsList`: `G4EmStandardPhysics_option4` + `G4DecayPhysics` +
`G4RadioactiveDecayPhysics` (тот же выбор, что предписывает
`skills/geant4-spectrum-pipeline/SKILL.md` для МК-шаблонов по нуклидам).

**Тестовый прогон**: точечный источник Cs-137 (661.657 кэВ), 100 мм от лицевой
грани корпуса, узкий конус (полураствор 5°) на кристалл, 1 000 000 событий,
~11 с. Результат (`run/output/*.csv`):

| Метрика | Значение |
|---|---|
| Полная эффективность (в конусе источника) | 10.78 % |
| Фотопиковая эффективность (в конусе, окно ±10 кэВ) | 2.50 % |
| Полная эффективность (абсолютная, относительно 4π) | 2.050×10⁻⁴ |
| Фотопиковая эффективность (абсолютная) | 4.761×10⁻⁵ |

Независимая грубая аналитическая оценка (телесный угол × `1-exp(-μx)`, μ/ρ(CsI,
662 кэВ) из NIST XRay Mass Attenuation Coefficients, интерполяция 0.6/0.8 МэВ) —
2.033×10⁻⁴, совпадает с MC-результатом полной эффективности в пределах ~1 %.
Расхождение с фотопиковой эффективностью (~4.3×) физически ожидаемо — формула
`1-exp(-μx)` считает ЛЮБОЕ взаимодействие, не полное поглощение.

**Это НЕ означает «модель провалидирована физически» в смысле сверки с
измерением** — это smoke-test, доказывающий, что вся цепочка (геометрия + физика
+ источник + скоринг) технически работает и даёт физически разумные по порядку
величины числа. Сравнения с реальными измеренными спектрами RC-103 (в
референсной папке есть файлы с «торий» в названии, но это, по всей видимости,
калибровочные измерения без паспорта активности, не аттестованный источник —
см. обсуждение с оператором) — отдельная, ещё не начатая задача.

## Ограничения модели

Количественно подтверждено `G4PVPlacement::CheckOverlaps()` 26.08.2026 (после фикса
P-001) — величина протрузии для каждого пункта, не только качественное описание:

**После P-004 (см. выше) четыре позиции сдвинуты — величины ниже относятся к
СОСТОЯНИЮ ДО этой правки** (историческая таблица overlap-классификации,
`../audit/project-incidents.md`), актуальные позиции — в самом GDML:

- Корпус-envelope: bbox-примитив без STL-формы; без USB-выреза (`USB_log` ДО P-004
  протыкал `Case_interior_log` на **1.75 мм** по +X и наружную грань корпуса — на
  **250 мкм**; после P-004 сдвинут внутрь полости — реалистичность позиции разъёма
  принесена в жертву работоспособности `BeamOn`, сознательный компромисс), без окна
  в ABS (`Display_window_log` ДО P-004 протыкал `Case_interior_log` на **1.3 мм**
  ПОЛНОСТЬЮ — это оказалось фатальным для `BeamOn`, не просто «фон»; `Display_LCD_log`
  — на **600 мкм**, частично; обе по −Z; после P-004 обе сдвинуты внутрь).
- Капсула: box вместо rounded-square 16×16 fillet R≈5; ниша SiPM Ø11×2.2мм не
  смоделирована → `SiPM_log` протыкает капсульную полость на **400 мкм**,
  `SiPM_carrier_log` протыкает стенку капсулы на **425 мкм** (оба — прямое следствие
  отсутствия ниши). **НЕ трогались P-004** — частичные overlaps, `BeamOn` их не
  крашит (мутационно подтверждено).
- PCB: монолитный бокс без U-cutout (как RC-110) → пересекается с капсульным узлом на
  **485 мкм**. Не тронут — частичный overlap.
- EMI-ткань: номинальный box ДО P-004 давал край **50 мкм** за границу полости;
  после P-004 сдвинута внутрь.
- ESR-плёнка (5 граней, каждая на 0.065 мм шире грани кристалла — умышленный нахлёст
  под light-tightness) слегка перекрывается сама с собой в углах куба: **12-32 мкм**.
  Не тронуто — частичный артефакт.
- Материалы LiPo/LCD/USB/EMI — упрощённые смеси.

**Итог после P-004**: `BeamOn` на официальном SSOT проходит без единого fatal
exception (мутационно проверено лично — до правки падал, после нет). Остаются
только частичные (не «полностью вне матери») overlaps как WARNING — не блокируют
расчёты, задокументированы как упрощения примитивов. Полная таблица (историческая,
до P-004) и разбор самой находки P-004 — `../audit/project-incidents.md`.
