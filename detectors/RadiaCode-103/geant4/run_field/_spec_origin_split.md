# Разделение счёта в домике по ПРОИСХОЖДЕНИЮ (три категории)

Задача: в прогоне с домиком показать, какая доля счёта порождена САМИМ СВИНЦОМ
(флуоресценция K-серии, тормозное), какая прошла сквозь свинец с рассеянием, а
какая попала в кристалл, вовсе не задев защиту (через открытый верх). Сейчас всё
это суммируется в один спектр, и вклад свинца из результата не выделить.

Правки в трёх файлах комплекта `run_field`. Формат CSV расширяется ДОБАВЛЕНИЕМ
колонок; существующие колонки и их смысл не меняются, иначе сломается весь
разбор в `analysis/`.

## Категории

Категория присваивается СОБЫТИЮ (одному первичному фотону поля), а не шагу:

1. `pb_born` — энергию в кристалле оставил трек, РОДИВШИЙСЯ в свинце домика.
   Признак: `track->GetLogicalVolumeAtVertex() == shieldLV`.
   Это флуоресценция Pb K-серии, тормозное и вторичные из свинца.
2. `pb_scat` — трек в свинце не рождался, но ПОБЫВАЛ в нём по дороге.
   Признак: идентификатор трека попал в множество треков, у которых был хотя бы
   один шаг с `preLV == shieldLV`. Комптоновское рассеяние идентификатор трека
   не меняет, поэтому такой признак ловит именно рассеянные.
3. `direct` — ни то, ни другое: фотон дошёл до кристалла, не заходя в свинец
   (через открытый верх либо мимо стенок).

Событие может смешивать категории. Правило: копить ТРИ суммы энерговыделения за
событие, а полное энерговыделение события класть в гистограмму той категории,
которая внесла НАИБОЛЬШУЮ энергию. Так спектр каждой категории остаётся
физически осмысленным (это спектр полного энерговыделения), а не обрезком.

⚠ При `shield=off` объём домика не существует, `shieldLV == nullptr`, и ВСЕ
события обязаны попасть в `direct`. Полная гистограмма при этом обязана
совпасть с прежней побитово — это проверяется прогоном.

## Файл 1: `Rc103FieldEventAction.hh` / `.cc`

Добавить к существующему `fEdep` три накопителя: `fEdepPbBorn`, `fEdepPbScat`,
`fEdepDirect` и множество `std::set<G4int> fTracksInPb`.

Публичные методы:
- `void AddEdep(G4double edep)` — оставить как есть (полная сумма);
- `void AddEdepByOrigin(G4double edep, int category)` — прибавить к нужному
  накопителю; категории: 0 = direct, 1 = pb_scat, 2 = pb_born;
- `void MarkTrackInPb(G4int trackID) { fTracksInPb.insert(trackID); }`
- `bool TrackWasInPb(G4int trackID) const { return fTracksInPb.count(trackID) > 0; }`

`BeginOfEventAction` обнуляет все четыре суммы и ОЧИЩАЕТ множество (иначе оно
растёт на весь прогон и съедает память — при 3·10⁸ событиях это фатально).

`EndOfEventAction` вызывает `fRunAction->RecordEvent(fEdep, category)`, где
`category` — индекс наибольшей из трёх сумм; при нулевом энерговыделении
категория роли не играет, передавать 0.

## Файл 2: `Rc103FieldSteppingAction.cc`

Режим `--check-norm` не трогать: он возвращается раньше, как сейчас.

В обычном режиме, ДО проверки `edep <= 0.0`, добавить пометку прохождения через
свинец: если `Rc103FieldDetectorConstruction::GetShieldLogicalVolume()` не
`nullptr` и `preLV` равен ему — вызвать `fEventAction->MarkTrackInPb(trackID)`.
Пометка обязана ставиться независимо от того, выделилась ли энергия: трек может
пройти свинец без потерь и депонировать всё в кристалле.

Далее, при депонировании в кристалле (`preLV == crystalLV`, `edep > 0`), кроме
существующего `AddEdep(edep)`, определить категорию:

```cpp
int cat = 0;                                  // direct
auto* shieldLV = Rc103FieldDetectorConstruction::GetShieldLogicalVolume();
if (shieldLV) {
  const G4Track* trk = step->GetTrack();
  if (trk->GetLogicalVolumeAtVertex() == shieldLV) {
    cat = 2;                                  // рождён в свинце
  } else if (fEventAction->TrackWasInPb(trk->GetTrackID())) {
    cat = 1;                                  // прошёл свинец с рассеянием
  }
}
fEventAction->AddEdepByOrigin(edep, cat);
```

Нужные заголовки: `G4Track.hh` уже подключён, добавить ничего не требуется.

## Файл 3: `Rc103FieldRunAction.hh` / `.cc`

- Сигнатура `RecordEvent(G4double edepMeV)` становится
  `RecordEvent(G4double edepMeV, int category)`; тело — как сейчас, плюс запись
  того же бина в `fHistOrigin[category]`.
- Поле: `std::array<std::array<long long, kNBins>, 3> fHistOrigin{};`,
  обнуляется в `BeginOfRunAction`.
- Счётчики попаданий по категориям: `std::array<long long, 3> fNHitsOrigin{};`.
- В метаданные CSV добавить три строки: `n_hits_direct`, `n_hits_pb_scat`,
  `n_hits_pb_born`.
- Шапку гистограммы заменить с `bin_keV,counts,cps` на
  `bin_keV,counts,cps,counts_direct,counts_pb_scat,counts_pb_born`.
  ⚠ Три первых колонки обязаны остаться на своих местах и с прежним смыслом —
  весь разбор в `analysis/` читает их позиционно.

## Проверка после сборки (обязательная, до длинных прогонов)

1. Прогон `shield=off` на 10⁶ историй: сумма `counts_direct` обязана равняться
   сумме `counts`, а `n_hits_pb_born` и `n_hits_pb_scat` — быть нулями.
2. Прогон `shield=on` на 10⁶ историй: `n_hits_pb_born` строго больше нуля, и в
   спектре `counts_pb_born` обязан быть виден максимум в районе 70–90 кэВ —
   это K-серия свинца. Если максимума нет, классификация неверна.
3. Сумма трёх колонок обязана равняться колонке `counts` в каждом бине.
