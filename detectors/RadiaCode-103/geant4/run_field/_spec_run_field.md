## Задача

Облучить провалидированную GDML-модель `gdml/detector/RC103_detector.gdml`
изотропным полем фотонов с заданным спектром флюенса и получить спектр
энерговыделения в `Crystal_log`, нормированный в **cps на 1 Бк/кг родителя**.

## Геометрия

- Мир: `G4Box` из `G4_AIR`, полуразмер 150 мм.
- Прибор: логический объём `RC103_device_log` из GDML (НЕ `World` парсера —
  тот 400 мм и не нужен), поставить в (0,0,0) без поворота, `pSurfChk=true`.

- `SetOverlapCheck(true)` на парсере.
- **R_SRC = 70 мм** — радиус виртуальной сферы розыгрыша. Это НЕ физический
  объём, никакого солида для неё не создавать. Обоснование числа:
  полудиагональ корпуса 123×34×17,5 мм равна 64,4 мм, 70 мм даёт запас 5,6 мм.

## Источник (ключевая физика — реализовать дословно)

Изотропное поле внутри выпуклой поверхности создаётся розыгрышем точки
равномерно по поверхности и направления **по косинусному закону** относительно
внутренней нормали. Не изотропно по направлению — именно косинусно, иначе поле
внутри не будет изотропным и вся нормировка развалится.

```cpp
// 1) точка равномерно по сфере радиуса R_SRC
const double cosT = 2.0 * G4UniformRand() - 1.0;
const double sinT = std::sqrt(1.0 - cosT * cosT);
const double phi  = twopi * G4UniformRand();
const G4ThreeVector n(sinT * std::cos(phi), sinT * std::sin(phi), cosT); // наружная нормаль
const G4ThreeVector pos = R_SRC * n;

// 2) направление ВНУТРЬ, косинусное относительно -n
const G4ThreeVector e3 = -n;                    // внутренняя нормаль
G4ThreeVector e1 = e3.orthogonal().unit();      // любой перпендикуляр
const G4ThreeVector e2 = e3.cross(e1).unit();
const double ct  = std::sqrt(G4UniformRand());  // cos относительно e3, косинусный закон
const double st  = std::sqrt(1.0 - ct * ct);
const double psi = twopi * G4UniformRand();
const G4ThreeVector dir = st * std::cos(psi) * e1 + st * std::sin(psi) * e2 + ct * e3;
```

Энергия — розыгрыш по кумулятивному распределению колонки `fluence_cm2_s`
из входного CSV; берётся центр бина (`E_keV` как есть, бин 2 кэВ).

## Нормировка (тождество Ф = 4N/S)

Для выпуклой поверхности площади `S` в изотропном поле с флюенсом `Ф`
число частиц, пересекающих её внутрь, равно `Ф·S/4` в секунду.

```
S     = 4*pi*R_SRC^2                 [см^2], R_SRC = 7.0 см
Ф     = fluence_total_cm2_s          [1/(см^2*с)] — ИЗ ЗАГОЛОВКА входного CSV
rate  = Ф * S / 4.0                  [1/с]
T_run = N_events / rate              [с]  — эквивалентное время экспозиции
cps(канал) = counts(канал) / T_run   [1/с на 1 Бк/кг родителя]
```

**Самопроверка чтения входа:** просуммировать колонку `fluence_cm2_s` и сравнить
с `fluence_total_cm2_s` из заголовка. Расхождение > 1% — напечатать WARNING с
обоими числами (не падать: последний канал в файле помечен как переполнение).

## ОБЯЗАТЕЛЬНАЯ самопроверка нормировки — режим `--check-norm`

Без неё работа не принимается: если нормировка неверна, все шаблоны неверны
одинаково, и по ним самим это не видно.

- Прибор НЕ загружать вообще (GDML не парсить).
- В центре мира — контрольный шар `G4_AIR` радиусом **20 мм**
  (`V = 4/3*pi*2.0^3 = 33.5103 см^3`).
- В `SteppingAction` накапливать суммарную длину треков **фотонов** внутри
  этого шара: `if (preStepLV == checkLV && particle == gamma) sumLen += step->GetStepLength();`
- Оценка флюенса track-length методом: `Ф_изм = sumLen / (V * T_run)`.
- Напечатать `Ф_ном`, `Ф_изм`, отношение. **Ожидание: 1.00 ± ~0.01.**
  Воздух на 7 см практически прозрачен, поэтому поле внутри равно полю на
  поверхности. Отклонение > 3% — дефект розыгрыша или нормировки, докладывать
  как провал, НЕ подгонять код под желаемое число.

## Физика

`G4EmStandardPhysics_option4`, `SetDefaultCutValue(0.05*mm)` — здесь важна
точность отклика в кристалле 10 мм и в тонких слоях обвязки (в `run_room/`
стоял 1 мм, но там задача была транспорт через 80 см бетона — другая).
Декей-физика НЕ нужна: первичные частицы — фотоны, не ионы.

## Выход

CSV: блок `metric,value` (`n_events`, `n_hits_in_crystal`, `flux_total_cm2_s`,
`surface_cm2`, `rate_per_s`, `t_run_s`, `cps_total`, плюс для `--check-norm`
`flux_measured_cm2_s`, `flux_ratio`), затем блок `bin_keV,counts,cps` с шагом
**1 кэВ, 0..2999 кэВ** (свёртка с FWHM делается потом в Python, поэтому сетка
мелкая и НЕсвёрнутая).

CLI: `rc103_field.exe <flux_csv> <n_events> <out_csv> [--check-norm]`
