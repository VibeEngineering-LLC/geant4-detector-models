# Дополнение к `run_field`: свинцовый домик (оценочный расчёт)

Задача: добавить в СУЩЕСТВУЮЩУЮ программу `run_field` опциональный свинцовый
домик вокруг прибора и прогнать пару «без домика / с домиком» в одинаковых
условиях, чтобы увидеть, как меняется спектр фона.

Ничего, кроме добавления домика и ключа CLI, менять НЕЛЬЗЯ: физика источника,
нормировка Ф = 4N/S, скоринг, формат выхода остаются как есть.

## Геометрия домика — РЕАЛЬНЫЕ размеры домика оператора

Числа сообщены оператором 15.08.2026 и записаны в
`detectors/RadiaCode-103/geometry/PbShield.hh:52-58`. Оттуда взяты только ЭТИ
числа как данные; сам файл и `RCDetector.*` использовать как код-образец
ЗАПРЕЩЕНО (указание оператора 27.08.2026 — старая модель детектора).

- полость: **150 x 150 мм в плане, высота 385 мм**;
- свинец: **50 мм** — стенки И дно;
- **верх ОТКРЫТ** (крышки нет);
- меди и кадмия НЕТ;
- материал — `G4_Pb` (NIST).

Наружный габарит: 250 x 250 x 435 мм.

## Посадка прибора — ВАЖНО, отступление от старой модели

В старой модели сборка стояла на дне полости. Здесь прибор ставится в
**геометрический центр полости**, и домик центрируется на начале координат
(0,0,0), где уже стоит прибор.

Причина строгая: сфера-источник имеет R_SRC = 300 мм и центрирована в (0,0,0).
При посадке на дно верхний угол домика уходит на sqrt(125^2+125^2+376^2) =
415.7 мм от центра, то есть ЗА сферу — источник оказался бы внутри свинца, и
расчёт стал бы бессмысленным. При центрировании полудиагональ домика
sqrt(125^2+125^2+217.5^2) = 280.3 мм < 300 мм, всё корректно.

Это ДОПУЩЕНИЕ оценочного расчёта, и его надо записать комментарием в коде.

## Реализация

- Ключ CLI `shield=on` / `shield=off` (по умолчанию **off**).
- Строить домик как разность объёмов либо как набор из 4 стенок + дно —
  на твоё усмотрение, но БЕЗ наложений: `pSurfChk=true` на всех постановках,
  и в логе не должно появиться ни одного НОВОГО overlap-предупреждения сверх
  8 уже известных (SiPM/carrier/ESR x3/дисплей/USB/PCB).
- **Обязательная проверка вместимости**: если прибор (габарит 123 x 34 x 17.5 мм)
  не помещается в полость 150 x 150 x 385 мм — печатать FATAL и завершаться,
  а не строить молча. Проверять фактом габаритов, а не «на словах».
- Проверка вложенности: полудиагональ наружного габарита домика обязана быть
  меньше R_SRC. Если нет — FATAL с обоими числами.
- В выходной CSV добавить строки `shield` (0/1), `shield_pb_mm`,
  `shield_cavity_mm`.

## Прогоны

Комната одна и та же в обоих прогонах, задаётся ключом `room=<X>x<Y>x<Z>`.
Конкретные габариты — ЛОКАЛЬНЫЕ данные оператора, в репозиторий не входят
(планировка жилого дома). Для воспроизведения расчёта возьмите любую
комнату разумного размера: на результат сравнения «с домиком / без домика»
её габариты влияют пренебрежимо, поскольку стены модели не радиоактивны,
а источник — сфера R=300 мм вокруг прибора.

Флюенс: `detectors/RadiaCode-103/results/wallion/wf_m1_K40.csv` и
`..._Tl208.csv` — двух нуклидов для оценки достаточно: K-40 даёт линию 1461 кэВ,
Tl-208 — жёсткие 2615 кэВ, и по ним видно, как домик гасит мягкую и жёсткую
части по-разному.

По 3e8 событий на каждый из четырёх прогонов:

1. `wf_m1_K40.csv`   + `shield=off` -> `output/est_K40_noshield.csv`
2. `wf_m1_K40.csv`   + `shield=on`  -> `output/est_K40_shield.csv`
3. `wf_m1_Tl208.csv` + `shield=off` -> `output/est_Tl208_noshield.csv`
4. `wf_m1_Tl208.csv` + `shield=on`  -> `output/est_Tl208_shield.csv`

Прогоны независимы — пускать параллельно.

4. Список overlap-предупреждений: новых быть не должно.
5. Ничего вне `geant4/run_field/` и `build/RadiaCode-103-field/` не менять,
   git не трогать.
