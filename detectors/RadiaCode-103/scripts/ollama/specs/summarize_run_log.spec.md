# Назначение
Суммаризатор логов прогонов Geant4: из логов на тысячи строк извлекает только факты и печатает JSON на stdout.

# Интерфейс командной строки
    python summarize_run_log.py <путь-или-маска> [<путь-или-маска> ...] [--explain] [--max-wait N]
Маски раскрывать через glob.glob; если маска ничего не нашла — считать её обычным путём.

# Что извлекать из каждого лога
1. Строки вида `RESULT <вид> <остаток>` — разобрать остаток на пары key=value регулярным выражением
   (\w+)=\s*([-\d.eE+]+|\S+). Сохранять номер строки, вид и словарь значений.
2. Блоки исключений Geant4: начало — строка, СОДЕРЖАЩАЯ подстроку `G4Exception-START`, конец —
   содержащая `G4Exception-END`.
   ВНИМАНИЕ: маркер стоит В СЕРЕДИНЕ строки, а не в начале — реальная строка лога выглядит так:
       -------- WWWW ------- G4Exception-START -------- WWWW -------
   Поэтому искать ТОЛЬКО поиском подстроки (`in` или re.search). Использовать str.startswith НЕЛЬЗЯ:
   при startswith блок не находится никогда и счётчик исключений молча выходит нулевым.
   То же касается строк `*** G4Exception : <КОД>` и `issued by : <текст>` — искать подстрокой.
   Сохранять номер строки начала блока, код, издателя.
3. Признаки падения: строки, где встречается Fatal, FATAL, `*** Break` или aborting (регистронезависимо).
   Сохранять номер строки и первые 200 символов текста.

# Требования к выводу
- JSON на stdout, ensure_ascii=False, indent=1.
- Верхний уровень: n_files, n_results, n_exceptions, n_fatal, files (список отчётов по файлам).
- Отчёт по файлу: file (абсолютный путь), size_bytes, n_lines, results, exceptions, exception_codes, fatal.
- exception_codes — словарь {код: сколько раз встретился}: одно и то же предупреждение Geant4 повторяется
  тысячи раз, в отчёт должен идти счётчик, а не тысяча одинаковых записей.
- В списке exceptions оставлять не более 5 образцов.
- У каждого извлечённого факта обязателен номер строки-источника (провенанс).
- Если файла нет — в его отчёт положить поле error, не падать.

# Ключ --explain
Добавляет в вывод поле ollama_summary — сводку по всей пачке от локальной модели.
ОБЯЗАТЕЛЬНО использовать:
    sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
    from _vram_guard import guarded_generate
Вызов строго с такой сигнатурой (у этой версии параметры генерации — ОТДЕЛЬНЫЕ аргументы, НЕ словарь options):
    resp = guarded_generate("qwen3-coder:30b", prompt, want_gpu=True, priority=50,
                            max_wait_s=<из --max-wait>, project="geant4-detector-models",
                            agent="geant4-log-summarizer", fmt="json", temperature=0, num_ctx=32768)
Ответ — dict; тело брать как resp.get("response", "{}"), затем json.loads.
Прямой requests.post ЗАПРЕЩЁН.
В промпт класть компактную выжимку (имя файла, до 3 наборов значений RESULT, exception_codes, число fatal),
а не сами логи. Просить у модели строго JSON вида {"summary": ..., "anomalies": [...], "verdict": "ok|warn|fail"}.
При ошибке разбора ответа вернуть {"ollama_failure": <текст ошибки>, "raw": <первые 500 символов>} — не падать
и не возвращать молча пустую сводку.

# Прочее
- Первая строка файла: # -*- coding: utf-8 -*-
- sys.stdout.reconfigure(encoding="utf-8", errors="replace") сразу после импортов.
- Файлы открывать с encoding="utf-8", errors="replace".
- Docstring модуля на русском: зачем нужен, и что факты извлекает python, а Ollama подключается только
  для сводки по пачке.
- Комментарии на русском, по делу.
# Приёмка (обязательна)
Сгенерированный файл считается годным только после ПОВЕДЕНЧЕСКОЙ проверки на реальных логах:
запустить на каталоге с логами прогонов и сверить с эталоном — число найденных RESULT И число
найденных исключений. Проверка наличия нужных строк в коде НЕ является приёмкой: версия от

из-за startswith вместо поиска подстроки.
