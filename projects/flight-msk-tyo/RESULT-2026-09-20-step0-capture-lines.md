# Результат шага 0 — захватные гамма-линии в Geant4 против базы IAEA PGAA

**Дата:** 2026-09-20. Разрешение оператора: «да» на порядок шагов 0–1. **Статус: по захвату — итог получен; неупругое рассеяние — см. отдельный раздел.**
**Что проверено:** реалистичны ли гамма-линии радиационного захвата, которые Geant4 11.4.2 рождает для материалов самолёта и людей.
Без этого «все линии объяснены» невозможно: интенсивности линий в салонном спектре определяются именно ими.

## Метод

Стенд `src/line_bench.cc`: тепловые нейтроны (2,53·10⁻⁸ МэВ) стартуют в центре сферы из материала M, записываются все гамма,
рождённые процессом `nCapture`. Число захватов оценено по энергетическому балансу: `Ncap = Σ Eγ / Sₙ` (нижняя граница).
Эталон — база IAEA PGAA (`promptgammas.xls`, `isotope.xls`, `research/data/`): интенсивность линии на захват
`y = (abund/100 · σγ) / Σ(abund/100 · σ₀)`. Сравнение — **после свёртки с разрешением CsI-детектора**
(ПШПВ 41,6 кэВ на 662 кэВ, ∝√E, значение из README донора), по окнам 500 кэВ: `scripts/compare_smeared.py`.
Побиновое сравнение линий признано непригодным: Geant4 кормит соседний уровень (Al: 7693 кэВ вместо 7724, ΔE = 30,6 кэВ = первый
уровень ²⁸Al), а различие в 30 кэВ детектор при ПШПВ ≈ 140 кэВ на 7,7 МэВ не видит.

## Что установлено

**1. Флаг фотоиспарения `SetUseOnlyPhotoEvaporation` на захват НЕ влияет.** Режимы 0 и 1 дали побайтово одинаковые гистограммы у всех 9 материалов;
лог печатает `Use only photo-evaporation 1`, то есть флаг принят, но не используется в канале захвата (проверено и программным вызовом, и командой
`/process/had/particle_hp/use_photo_evaporation`). Режим 4 (`Shielding`) для захвата тоже совпал с режимом 0.

**2. `FTFP_BERT_HP` и `FTFP_BERT` (без HP, захват через `G4NeutronRadCapture`) дают практически один спектр захвата.** Значит, для этих изотопов
G4NDL 4.7.1 не несёт дискретной первичной схемы, и «HP» идёт по тому же пути фотоиспарения. Это наблюдение; причина по исходникам не проверена (там
доступны только заголовки).

**3. Линии водорода в порядке.** ¹H(n,γ): 2223 кэВ = 38 996 из 39 356 гамма (99,1 %); линии ¹²C: 4945 и 1856/3089 кэВ есть, но ветвление
4945 : 3684 : 1262 у Geant4 128 : 5 : 4 против 1 : 0,47 : 0,48 по базе.

**4. Высокоэнергетические первичные переходы у Al, Fe, Cu резко занижены** (окна вблизи Sₙ, где база полна, поэтому неполнота базы не объясняет):

| Элемент | окно, кэВ | база IAEA, γ на захват | Geant4 (режим 0 / 2) | Geant4 / база |
|---|---|---|---|---|
| Fe | 7500–8000 | 0,4252 | 0,01104 / 0,01080 | 0,026 (в 39 раз ниже) |
| Cu | 7500–8000 | 0,2635 | 0,01092 / 0,01295 | 0,041–0,049 (в 20–24 раза ниже) |
| Al | 7500–8000 | 0,2484 | 0,05615 / 0,05441 | 0,22 (в 4,4 раза ниже) |
| Cu | 7000–7500 | 0,1196 | 0,01426 / 0,01682 | 0,12–0,14 |
| Fe | 7000–7500 | 0,05402 | 0,02355 / 0,02347 | 0,44 |

**5. Оговорки, без которых вывод неполон.**
* База IAEA сама неполна: по ней `Σ E·y` равна 6655 кэВ (86 %) у Al, 6255 кэВ (82 %) у Fe, 5010 кэВ (63 %) у Cu, 7807 кэВ (92 %) у Si от Sₙ, кратность
  1,5–2,0 против 2,5–4,1 у Geant4. Поэтому окна средних энергий, где Geant4 «больше базы» (1,8–4,5 раза по медиане), доказательством ошибки Geant4
  не служат. Доказательство — только п. 4.
* Ncap оценена по Sₙ ОДНОГО изотопа (Al-28, Fe-57, Ti-49, Cu-64, Si-29); у Fe, Ti, Cu, Si природная смесь содержит изотопы с другой Sₙ
  (Fe-54 → 9298 кэВ, Ti-47 → 11 626 кэВ и др.), поэтому Ncap для них — приближение, а окна выше Sₙ у Ti — физичны.
* Полная картина в CsI детекторе зависит ещё от эффективности регистрации на 6–8 МэВ, которая мала; вклад этих линий в САЛОННЫЙ спектр
  оценивается только расчётом этапа I–II.
* Сравнение по свёртке использует разрешение донора, принятое по числу, а не по собственной записи (`CFG1` §2 п.17).

## ПРИЧИНА ЗАНИЖЕНИЯ — разобрано 2026-09-20 по указанию оператора

### Установлено фактами

**1. Данные в поставке Geant4 есть и они верные.** Для Fe-56 файл `G4NDL4.7.1/Capture/FSMF6/26_56_Iron.z` содержит
**193 дискретные линии, сумма вероятностей ровно 1,0000**, в том числе 7645,54 кэВ (0,1307) и 7631,14 кэВ (0,1554).
Для Al-27 файл `Capture/FS/13_27_Aluminum.z` — 84 линии, сумма выходов 1,704, в том числе 7726 кэВ (0,300) и 7695 кэВ (0,050).

**2. Модель эти данные НЕ использует.** Решающая сверка: интенсивности линий в физ-листе **с** нейтронными данными
(`FTFP_BERT_HP`) и **без** них (`FTFP_BERT`, где захват идёт через `G4NeutronRadCapture` и всегда через `G4PhotonEvaporation`)
совпадают:

| Линия | в файле G4NDL | `FTFP_BERT_HP` | `FTFP_BERT` (без HP) |
|---|---|---|---|
| Al, 7690–7700 кэВ | 0,0500 | 0,0542 | 0,0524 |
| Fe, 7625–7640 кэВ | 0,1554 | **0,0030** | **0,0029** |

Совпадение двух путей означает: в обоих случаях работает статистическая деэкситация `G4PhotonEvaporation` по базе уровней
`PhotonEvaporation6.1.2`, а дискретные данные захвата не применяются. Занижение линии Fe — **в 52 раза относительно
собственных данных поставки**.

**3. Следствия совпадают с этим объяснением:**
* кратность 2,90–2,99 гамма на захват против 1,70 по данным G4NDL — каскад длиннее, спектр мягче;
* флаг `SetUseOnlyPhotoEvaporation` (и команда `/process/had/particle_hp/use_photo_evaporation`) не меняет ничего:
  гистограммы всех 9 материалов побайтово равны — переключать нечего, этот путь уже работает;
* **водород воспроизводится идеально** (2223 кэВ, 99,1 %) — у дейтрона нет промежуточных уровней, статистической
  альтернативы прямому переходу не существует;
* у Al-28 верхние уровни базы (7502, 7592, 7654, 7669, 7700 кэВ) вообще **не имеют схемы распада** — переходов у них не записано.

**4. Код условия** (`G4NeutronHPCaptureFS::ApplyYourself`, ветка данных против фотоиспарения):
`if (HasFSData() && !fManager->GetUseOnlyPhotoEvaporation())`. Наблюдаемое поведение отвечает случаю `HasFSData() == false`.
**Почему именно ложно — не установлено:** отладчика не применял, переменная `G4PHP_VERBOSE` вывода о загрузке файлов не дала,
исходников `.cc` в установке нет (только заголовки), код прочитан с GitHub.

### Проверенная и ОПРОВЕРГНУТАЯ гипотеза (записано, чтобы не возвращаться)

Была версия: захватный уровень Fe-57 в базе (**7646,70 кэВ**) лежит на 0,53 кэВ ВЫШЕ энергии связи (7646,17 кэВ), поэтому
ядро не может сесть на него и уходит в статистический канал; у этого уровня в базе есть переход 7632 кэВ с относительной
интенсивностью 100 (доля 0,47 на захват). **Предсказание до опыта:** добавка нейтрону ~1 кэВ поднимет энергию возбуждения выше
уровня, и линия 7632 вспыхнет в десятки раз. **Опыт (`results/linebench/scan_Fe_E*.csv`, 6 точек):**

| E нейтрона | возбуждение, кэВ | линия 7632, на захват | кратность |
|---|---|---|---|
| 2,53·10⁻⁸ МэВ | 7646,17 | 0,0027 | 2,99 |
| 5·10⁻⁴ МэВ | 7646,66 | 0,0029 | 2,98 |
| 1·10⁻³ МэВ | 7647,15 | 0,0036 | 2,98 |
| 1·10⁻² МэВ | 7655,99 | 0,0038 | 2,98 |

Роста в десятки раз нет (всего в 1,4), кратность постоянна. **Гипотеза отвергнута опытом.** Заодно отвергнута более ранняя
догадка, что линия Al 7693 кэВ — это линия G4NDL 7695 с учётом отдачи: в режиме без нейтронных данных она такая же.

### Подтверждение из литературы (это не наша особенность)

* **G4CASCADE**, [arXiv:2408.02774](https://arxiv.org/abs/2408.02774): «модули G4NDL и G4PhotonEvaporation не воспроизводят
  известные гамма-линии и корреляции, релевантные при 2–15 МэВ»; G4PhotonEvaporation сохраняет энергию, но даёт лишние и
  недостающие гамма с неверными интенсивностями. Модуль опубликован для Geant4-10.
* **Форум Geant4**, [тема 6504](https://geant4-forum.web.cern.ch/t/thermal-neutron-capture-gamma-spectra-give-major-disagreement-with-nndc-data-base-for-some-isotopes/6504):
  расхождение с NNDC для ⁵⁸Ni, ¹⁵⁵Gd, ¹⁵⁷Gd при любых сочетаниях параметров HP; программа добавляет фиктивные гамма для
  сведения баланса; рекомендация — проверять спектр для каждого нового изотопа.

### Что это меняет для нашего расчёта

Дефект затрагивает **все** захватные линии конструкции и, что важнее, **сам кристалл**: Cs-133 и I-127 идут по тому же пути
(`FSMF6`-данные, которые не применяются). Настройками (физ-лист, флаг, порог, энергия нейтрона) он не лечится — проверено.

## Что это значит для расчёта (предложение, ждёт «да» оператора)

Захватные линии в основном расчёте (люди — Н, N, C; обшивка — Al, Cu, Fe; кристалл — I, Cs) от Geant4 «как есть» для интенсивностей
высокоэнергетических переходов ненадёжны. Предлагаю:

1. На этапе I писать **карту захватов** (положение, нуклид-мишень, время) — она нужна в любом варианте и даёт огромный выигрыш по статистике.
2. На этапе II считать **два варианта** эмиссии: (А) гамма прямо от Geant4; (Б) гамма из базы IAEA PGAA по нуклиду, в который захвачен нейтрон
   (независимый розыгрыш линий по интенсивностям, неполнота базы — отдельная строка отчёта).
3. В отчёте показать разницу А и Б как систематику захватной части, а не выбирать «правильный» без сверки с измерением
   (записи прибора с рейса нет; опубликованного размеченного спектра в салоне на 10–12 км найти не удалось).
