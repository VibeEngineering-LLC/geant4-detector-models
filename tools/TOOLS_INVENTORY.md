## Публикация и безопасность

### `tools/check_paths.py`
- **Назначение**: проверка репозитория перед коммитом в публичный репозиторий —
  абсолютные пути, фамилии и инициалы, заводские номера, почта, токены.
- **Почему обязателен**: попав в историю git, локальный путь или фамилия
  остаются там навсегда; вычистить задним числом нельзя.
- **Статус**: ACTIVE.
- **Запуск**: `python tools/check_paths.py [корень]`; возврат 1 при находках.

### `tools/check_csv.py`
- **Назначение**: прочитать каждую таблицу в `detectors/*/results/` штатным
  `csv.reader` и сверить число полей в строке с шапкой.
- **Почему обязателен**: `results/` — это то, что читает внешний потребитель, и
  читает обычным `csv.DictReader`. Незакавыченная запятая внутри значения не
  роняет чтение, а ТИХО сдвигает поля: в `efficiency_curves.csv` 48 строк обеих
  точечных кривых («точечный, 25 см») отдавали `E_keV` = «ОТКРЫТА», а
  `eps_net` = число энергии. Объёмные кривые при этом читались верно, поэтому
  дефект и не всплывал.
- **Где живёт проверка**: `common/py/csvio.py` — ОДНА реализация на весь
  репозиторий. Она же вызывается при каждой записи (`csvio.write`), она же
  запрещает запятую внутри значения: потребитель разбирает выгрузку по
  позициям, и закавыченное поле ему не помогает. Копия сторожа в
  `export_curves.py` успела разъехаться с этой по обращению с
  комментариями — убрана.
- **Статус**: ACTIVE.
- **Запуск**: `python tools/check_csv.py [файл...]`; возврат 1 при находках.
  Входит в `recalc_all.py` ВСЕГДА, в том числе при `--only`.

### `tools/anonymize.py`
- **Назначение**: обезличивание спектров и паспортов — удаление поля
  `OPERATOR`, замена заводских номеров приборов на `SN-nn`, номеров
  сертификатов источников на `SRC-nn`, в содержимом И в именах файлов.
- **Особенность**: номера, не перечисленные в карте, получают автопсевдонимы
  `SRC-Ann`; соответствие подлинным номерам **не публикуется**.
- **Защита формата**: перед правкой проверяет на одном `.spe`, что сумма
  отсчётов до и после совпала — в `.spe` ЛСРМ отсчёты упакованы двоично.
- **Статус**: ACTIVE.
- **Запуск**: `python tools/anonymize.py <каталог>`; для проверки формата
  нужен `SPECTRAVIBE_ROOT`.

## Получение эталонных данных

### `tools/fetch_efr.py`
- **Назначение**: скачивание кривых эффективности `.efr`/`.efa` из
  spectravibe-toolkit с перекодировкой CP1251 и разбором точек.
- **Статус**: ACTIVE.

### `tools/fetch_kit_xml.py`
- **Назначение**: скачивание комплекта поверки в XML BecqMoni (все геометрии).
- **Особенность**: качает через git-дерево и SHA блобов, а не через
  `contents/<путь>` — в путях кириллица, и URL-кодирование её ломает.
- **Статус**: ACTIVE.

### `tools/fetch_bg.py`
- **Назначение**: скачивание усреднённых фоновых спектров установки.
- **Статус**: ACTIVE.

> (`detectors/Gamma-1S/reference/lsrm/`), поэтому скачивание нужно только для
> обновления или для других детекторов.

## Библиотека разбора — `common/py/`

### `common/py/paths.py`
- **Назначение**: корни путей из переменных окружения; в коде нет ни одного
  пути, привязанного к машине.
- **Переменные**: `GEANT4_ROOT`, `G4MODELS_BUILD`, `G4MODELS_REF`,
  `G4MODELS_MEASURED`, `SPECTRAVIBE_ROOT`.
- **Статус**: ACTIVE.

### `common/py/becqmoni.py`
- **Назначение**: чтение спектров BecqMoni XML, площади пиков с
  трапецеидальной подложкой, измерение ПШПВ по самому пику, **уширение
  модельного спектра до разрешения прибора** (`broaden`, `area_broadened`).
- **Ключевое**: площадь из модели и из измерения обязана сниматься ОДНИМ
  окном, иначе бленды считаются по-разному (ошибка до 1,5 раза).
- **Смежный аналог**: `gamma/io/becqmoni_xml.py` в spectravibe-toolkit —
  при развитии сверяться.
- **Статус**: ACTIVE.

### `common/py/contam.py`
- **Назначение**: проверка чистоты фоновых полок — попадает ли в них сильная
  соседняя линия. Загрязнённые точки **исключаются**, а не подгоняются.
- **Аналога в spectravibe-toolkit не найдено** — дополнение этого репозитория.
- **Статус**: ACTIVE.

## Самоаудит документов

Два инструмента разных ярусов. Механика проверяет ЧИСЛА, локальная модель —
СУЖДЕНИЯ; ни один не заменяет другого, и оба не ловят ПРОПУСК (утверждения,
которого в документе нет).

### `tools/audit_numbers_vs_source.py`
- **Назначение**: сверить каждое число markdown-документа с текстом
  первоисточников (PDF). Делит числа на три корзины — найденные в источнике,
  отсутствующие на строке с меткой производного, отсутствующие без метки —
  и печатает две последние как блок «требует толкования».
- **Почему нужен**: документ-пересказ статьи копит числа, часть которых
  наши, часть чужие, а часть — опечатки. Отличить их глазами нельзя.
- **Не судит о смысле.** Толкование каждой находки — за человеком.
- **Статус**: ACTIVE.
- **Запуск**: `python tools/audit_numbers_vs_source.py --doc <md> --src <pdf>
  [--src <pdf> ...] [--json <out>]`; возврат 1 при находках.
- **Известное свойство**: десятичная точка математического шрифта
  извлекается из PDF как ДВОЕТОЧИЕ (`5:96` вместо `5.96`) — нормализуется
  при чтении. Без этого дробные числа из формул не находятся никогда, и
  инструмент даёт ложную тревогу втрое (проверено: 49 находок против 16).
- **Приёмка (мутационная)**: добавленное выдуманное число, подменённый
  расчёт и подменённый параметр — все три ловятся сверкой СОСТАВА корзин.
  Сверка КОЛИЧЕСТВА находок ловит только добавление и слепа к подмене:
  проверено, 1 из 3.

### `tools/audit_doc_sterile.py`
- **Назначение**: стерильная вычитка документа локальной моделью (Ollama).
  Режет документ по разделам, каждую часть подаёт с критериями проверки.
- **Стерильность**: модель получает ТОЛЬКО текст и критерии. Ни авторства,
  ни выводов автора, ни ожидаемых ответов в промпте нет — иначе это не
  проверка, а подтверждение названного ответа.
- **Статус**: ACTIVE.
- **Запуск**: `python tools/audit_doc_sterile.py <md> [--crit <файл>]
  [--model qwen3.6:27b] [--chunk 14000]`.
- **Зависимость**: `guarded_generate` из скилла workflow. Путь профиля НЕ
  зашит: берётся из `CLAUDE_WORKFLOW_SCRIPTS`, иначе из домашнего каталога
  текущего пользователя.
- **Критерии — сменные**, в отдельном файле. Готовый набор:
  `tools/_crit_method_revision.md` (7 классов дефектов: подмена статуса
  утверждения, чужой вывод, приписанный источнику, перенос без обоснования,
  внутреннее противоречие, физическая ошибка, непроверяемый критерий,
  неоднозначность). Правило написания критериев: **ожидаемых ответов в них
  быть не должно**.
- **Мера качества**: на ревизии метода 05.09.2026 дал 5 находок, 4 приняты,
  1 отклонена (термин, определённый вне поданного фрагмента — цена
  стерильности). Одна из принятых сняла неверный вывод автора.

`tools/_spec_audit_numbers_vs_source.md` — спека, по которой сгенерирован
первый из инструментов. Хранится рядом: правка инструмента начинается с
правки спеки.


## Обезличивание: карта лежит ВНЕ репозитория

`tools/anonymize.py` не содержит ни одной подлинной фамилии и ни одного
подлинного номера — карта соответствий это ключ обратного опознания, и
опубликованная вместе с данными она отменяет обезличивание. Путь к карте
задаётся переменной `ANON_MAP`, формат описан в начале скрипта.

```bash
ANON_MAP=<карта.json> SPECTRAVIBE_ROOT=<корень>     python tools/anonymize.py detectors/Gamma-1S/reference --verify
ANON_MAP=<карта.json> python tools/check_paths.py
```

Каталог указывается явно и обязан быть каталогом ДАННЫХ: прогон по корню
репозитория портит разметку и исходники (в markdown `#` — заголовок, в CSS —
цвет, в питоне — комментарий) и доходит до самого инструмента. Обе программы
теперь отказываются работать в таких условиях, но полагаться на это не надо.

`--verify` требует `SPECTRAVIBE_ROOT`: целость каждого правленого `.spe`
проверяется штатным читателем ЛСРМ — сумма отсчётов до и после обязана
совпасть.

Без `ANON_MAP` проверка `check_paths.py` работает только по общим шаблонам и
предупреждает об этом. Точная проверка по карте — единственная надёжная.
